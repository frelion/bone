01 / SYSTEM DESIGN

让每一次输入，
带着有限、可追溯的上下文开始。

长对话的原始事实保存在 Session journal。App 为每个输入选取历史摘要与最近事实；Core 再组合当前 Job 的工作集；Adapter 将它们装入模型请求。摘要可以重建，原始事实始终保留。

设计的中心：一个输入级的历史边界。 输入提交到位置 S，就绑定 S 之前的历史 W = S − 1。后续工具结果沿 Core 记录流继续进入 Job；外部写入安全状态由实时门禁检查。
02

保留执行基座，补齐 Session 记忆

当前代码已经有 Job 压缩和持久日志。真正变化的是背景的归属、生成方式和历史边界。

CURRENT · 当前实现

背景绑定 Runtime

  • tools::background() 从 SessionSeq(0) 扫描公开历史。
  • 在 context_bytes / 4 内保留最近完整事件，缺失只标 omitted: bool。
  • Kernel.background 被整个 Runtime 复用；后续输入没有独立历史水位。
  • 已有 Core Job checkpoint、分页 RecordView、durable journal 和 write gate。
PROPOSED · V1 目标

背景绑定每一次输入

  • App 新增私有 session_context.rs，复用 journal 和 document storage。
  • 提交时保存 ContextBasis(W, H)，固定历史截止点和摘要版本。
  • 以 immutable checkpoint + 有界 tail 构造背景，明确显示未装入区间。
  • 沿 InputEntry → Routing → JobContext 传递背景；Adapter 增加最终容量检查。

改动边界：不新增 crate 或第二份事件日志。Session checkpoint 只传递认知；现有 Job 状态机、Record 权限和外部写入安全边界继续负责执行。

03

跟着一个输入走完链路

示例请求：“继续检查迁移方案，确认后再发布。”以下数字与内容仅用于说明设计，不是运行记录。

多个输入如何合流？

同一 routing 聚合多个输入时，建议采用其中最新的 basis 作为共享背景；所有待处理输入仍显式保留在 CoordinateInput.inputs。单个输入的 durable basis 不被覆盖。背景中更早输入的重复呈现需按 InputId 去重，不能删掉本轮待处理请求。

回复与子 Job 如何继承？

回复进入已有 Job 时更新该 Job 的背景，并沿用 revision / call invalidation 规则。新 child 继承创建时 parent 的背景；已存在的 child 不自动换背景，后续信息通过显式 delivery 传入。

“读过”不是“读完整个文件”。 Core 的 read_through 记录已交付的通知水位。大工具结果可能只展示了一页；摘要必须保留未读正文的来源与游标，不能把部分阅读描述成完整验证。Job → Session 仅通过 public_agent_event 明确公开的结果进入历史，私有 Note / checkpoint 不直接进入 Session 摘要。

Session 摘要怎样提交？

1 · 读取旧 head记录 document revision 与 H；选择完整 public 前缀至 Wc。
→
2 · 生成 draft上一份摘要 + 完整新增前缀；模型输出 summary 与 evidence。
→
3 · 验证长度有界，evidence 来源合法，through 前进；不导入私有记录。
→
4 · 原子提交写 immutable checkpoint，并 CAS 更新 head；冲突即丢弃 draft。

低优先级、每 Session 单飞。失败和 crash 不改变 head；CAS 冲突从新 head 重建，不合并两份摘要。已绑定旧 H 的 queued input 继续读取旧 checkpoint，因此 V1 不清理这些文档。模型摘要的事实准确性不能由结构校验保证，evidence 用于回查。

06

装不下时，明确省略什么

两个预算边界分别验收。所有彩条仅表示组成关系，长度不代表已确定的配额。

第一层 · Core DTO 字节预算 CURRENT

当前输入 / spec / constraintsSession backgroundJob checkpoint + records工具 / calls / children

serde_json 后的完整 DTO ≤ context_bytes。背景条目的 label + content 长度之和不等于 DTO 大小，转义和结构开销也要算。必要字段自身超限必须明确失败。

第二层 · 最终 Provider 请求 PROPOSED

instructions序列化 Core DTOschema / 协议包装输出预留

在最终请求装配后做 provider-aware admission；超限在发送前返回 CallError。token estimator、模型 window 来源与保守余量尚待定，不能声称当前已有精确 token 保证。

Session 背景的裁剪顺序

  1. 先预留必要元数据、缺口说明与独立安全提示。
  2. 装入 basis 固定的有界 checkpoint。
  3. 从最新事件向前选择能放入的连续完整 tail。
  4. 将未装入的范围显式标成 (H, T]；提供 session_history 回读位置。

建议使用连续后缀，避免跳过中间大事件后制造多个隐蔽缺口。预算不足以表示必要信息时返回错误，不静默删除。

一个超大的事件怎样读？

背景不截断完整 event；通过显式历史回读分页。建议 cursor 由 SessionSeq + UTF-8 offset 构成，返回 next_offset。

event = SessionSeq(97)
offset = 0
next_offset = 4096  // 示例边界

下一页继续 event 97，不能跳到 98

checkpoint 缺失 / 损坏应报错或显式退回原始历史，不把它当成“已覆盖”；build 失败不能推进 durable head。

压缩不是隐藏丢失。 Session through 表示已处理的 public 历史前缀；原文不一定逐字出现在摘要。未放入的 tail、未读工具页和不可压缩的安全状态，必须分别表达。
07

失效路径也有确定的结果

上下文帮助新的工作理解过去。执行状态和外部副作用仍遵守原有持久化与门禁规则。

触发情况系统处理后续模型看到什么
输入已持久化，还未交给 Runtime保留 Queued；重新构造同一 basis 的背景。原 W / H 的历史，外加当前安全提示。
输入已进入旧 Runtime，进程崩溃未终态输入变 Interrupted；旧 Job / Call 引用 stale。公开的中断事实；用户“继续”产生新输入和新 Job。
外部写已发出，回执未知按现有恢复规则进入 Unknown / reconcile；write gate 阻止危险重试。明确的未解决写提示，不能据摘要认定成功或失败。
旧 Worker / 压缩调用结果迟到Core revision / active call 门禁拒绝失效提交。只有被合法接受的结果进入对应事实流。
Session 摘要期间 head 被推进CAS 失败，丢弃 draft；从新 head 重试。仍读取已绑定的 immutable checkpoint。
模型请求最终超窗口拟议 Adapter admission 在发网前明确报错。不伪造完成；不凭空删除必要约束。自动缩减重试策略待定。
Unknown 不能被摘要“解决”。 即使历史写着“计划发布”或模型声称“已经完成”，未解决写入仍由 durable 写入记录决定。只有显式 resolution 才能改变该状态。
08

从设计到实现，按边界逐步落地

本页完成设计表达；下列实现与新增测试均未在本次完成。先闭合输入链路，再加入异步摘要和最终请求预算。

SLICE 1 / APP

保存输入 basis

StoredInput 迁移；accept_input 同事务绑定 W / H，保持 RequestId 幂等。

SLICE 2 / APP

构造有界背景

session_context、checkpoint 读取、tail 范围与显式 recall；安全 overlay 独立处理。

SLICE 3 / CORE

背景跟随输入

post_with_context、routing 合流、reply 更新、child 继承；移除全局 background。

SLICE 4 / APP

异步 Session 压缩

窄模型契约、单飞调度、draft 校验、immutable document 与 CAS head。

SLICE 5 / ADAPTER

回读与容量准入

大事件 UTF-8 分页；最终 provider request 估算、输出预留与失败行为。

LATER / 独立设计

物理 retention

V1 保留 raw journal 和 Record。删除策略需单独证明 evidence 与历史引用闭包。

已收敛与仍需决定的内容

已收敛方向

App 持有 Session 记忆；Core 保留 Job 私有工作集；输入绑定 W / H；public bridge 控制跨层流动；CAS 更新摘要；原始事实不删除。

V1 排除：统一 ContextFrame、第二份 Ledger、向量检索、DAG merge、旧 Job 自动恢复。

仍需定接口

实时 safety overlay 的刷新入口；最终 provider 容量来源；background 缺口的结构化表示；Session compaction 触发阈值。

本轮补充建议：旧输入用 None 区分缺失 basis；tail 取连续后缀；安全提示不永久冻结在输入背景中。
