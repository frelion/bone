最小闭环已落地
01

先分清三个名字

Kernel 是状态裁决代码，Router 是轻模型，Runtime 负责执行和持久提交。

Router：把原话交给负责人

只有 Assign / Read / Clarify。选择已有 root 或新 root，附短说明；不规划技术步骤、不执行工具。

Worker：理解、规划和执行

收到原话后自己计划，用 Note 记过程、Delegate 分任务，可以纠正 handoff 的理解并向用户澄清。

当前所有 Worker 共用 worker 模型配置。独立的“反驳后原子转交负责人”协议尚未实现。
02

一份事实，两种记忆

Session 保存共同可见的对话；Job 保存某项工作的获准过程。

Session 公共背景

包含用户 Input、公开 Reply、向用户提出的 Clarification，以及 user-owned root 的 Published 和 Outcome。问题与回答一起保留，避免只记住“第二个”却丢失选项。私有笔记、child Published、child Outcome、工具全文不会自动进入。

独立 SessionCheckpoint + 最近公共原文。

Job 局部上下文

输入投递、工具结果、私有 Note、子任务结果，受 owner 和显式引用权限控制。

自己的 checkpoint + 已读/未读工作记录。

原始 Record 保留一份，可按来源分页回读。摘要覆盖一条请求，不代表它已经被审阅或完成。
03

每次调用怎样拿上下文

准备调用时读取最新已提交公共背景；开始后固定这一份请求。

Router = 原始输入 + 当前约束 + Session 背景 + root 目录页
Worker = 原始输入与 Job 必要状态 + Session 背景
         + Job 摘要和记录 + 工具定义

排队期间产生的公开事实可以进入之后的调用。没有每输入 W、历史 pin 或旧版本摘要树。公共原文重复项按来源去重，摘要语义重复暂时接受。

04

放不下时，先分页再摘要

检查的是整次请求，不是 Session 和 Job 各自过关就可以相加。

组装 → 测量完整 Core DTO
  放得下 → 开始调用
  放不下 → 工具大正文分页 → 选择真正可压缩的旧前缀
         → compact 草稿 → 校验并提交 → 重新组装

Session 的合法前缀

公开历史的完整前缀，保留最近公开记录。不等待所有 Job 已读；追加新尾部不会使旧固定前缀草稿失效。

Job 的合法前缀

当前 revision 中有效 Worker 已读的记录。未读投递保持未读，工具剩余正文仍可回查。

两者共用 ModelPort::compact，用 CompactScope 区分范围。摘要必须非空、有输出上限且实际缩小；无前缀或无收益就明确失败。

当前只有同步按需压缩，没有后台软阈值。必要原话或约束本身太大时明确报错，不用反复摘要掩盖容量问题。
05

记忆跨重启，由 Core 负责

Session 的记忆延续，不是重新启动一段旧网络调用。

Kernel 产生候选状态与新 Record
  → Runtime 调用 DurablePort 原子提交
  → 成功后发布状态，启动依赖动作

重启：DurableRestore（结构化快照 + 原始记录）
  → 恢复输入责任、权限、约束、摘要
  → 隔离旧调用，明确中断未完成执行

commit_id 保证幂等，expected_revision 检查冲突。端口返回错误必须表示确定未提交；不确定确认由端口内部解决。Unknown 外部写等待核查，不盲目重放。

App 实现 SQLite DurablePort、产品视图、配置与 Workspace 写门禁。恢复统一由 Core 记录与摘要提供记忆。仅接受当前持久协议，不迁移旧格式或猜测缺失字段。

06

哪些已完成，哪些以后再说

A、B、C 的最小闭环已在代码中实现。

已完成

  • 轻 Router 与 Worker 规划执行
  • 输入审阅屏障与失败/取消恢复
  • Core durable 提交与恢复
  • Session 公共投影与独立摘要
  • Session / Job 组合预算和按需压缩
  • 原文回查、可见性与恢复回归测试

未来候选

  • 负责人原子转交
  • 有界输入自动拆批
  • 按任务选 Worker 模型
  • 精细 provider token 容量接口
  • 后台压缩、惰性加载与回收
模型 DTO 有界，不代表进程内存有界。摘要可能遗漏，协议校验和原文回读不等于语义无损；仍需长对话质量评测。
