# BONE TUI 新设计提案

状态：待评审，2026-09-10。只新增设计与研究材料，未修改产品代码。当前实现基线 `9870ed3`；本机 OpenCode `1.18.29`。

## 设计结论

保留你的三栏：左侧切换 Session，中间持续对话，右侧深入当前对象。此次重做的是三栏内部的阅读节奏、组件状态和操作闭环。默认右栏继续留白；不把留白当成缺陷，不擅自填 Dashboard。没有全局动作栏、设置页、创建会话对话框，也不出现横跨三栏的 Composer。

推荐采用接近 OpenCode 的中性灰阶与少量暖色强调。终端字号不分大中小，层级由字重、行距、起线、底色构成。用户消息有浅底和细竖线，Agent 正文直接在画布上。把“正在做什么”放在紧凑的活动行，把“需要你做什么”明确放在输入区附近。

先看 [界面稿总览](BOARDS.md)。所有稿件按真实字符格绘制：ASCII 一格、中文两格，14px 字号、9×20px 字格。SVG 是设计稿，不是实现截图；内容是明确的示例。实际运行证据另存于 `evidence/`，对应 `boards/actual-*`。

| slash 描述紧跟不同长度命令，列不对齐；最小尺寸菜单只露前三项 | `bone-slash-80.ansi`、`bone-40.ansi` | 固定命令列、描述列，选择滚动可达，底部固定一行当前操作提示 |

## 从 OpenCode 吸收什么

| 参考观察 | BONE 采用 | BONE 保持自己的设计 |
|---|---|---|
| 本机空态输入区将编辑、模型信息、快捷提示分层 | 同样三层，正文与提示不抢位置 | 输入区始终归中栏，不照搬首页 logo 和居中全屏入口 |
| 上游 prompt 自适应高度、浅底、左侧强调线，session 有统一横向内边距 | 单一输入表面、两格外侧留白、三格文字缩进 | 焦点强调色不表示 Agent 角色；不增加角色切换按钮 |
| 本机命令菜单有搜索、分组、右对齐快捷键 | 搜索/过滤、固定列宽、选择反馈 | 菜单锚定 Composer 上方，不遮蔽三栏整体、不另造设置页 |
| 上游 session 用 Markdown 组件与可控制的工具详情 | 正文层级和工具摘要/展开 | 工具详情必须来自 App；不显示未经投影的私有推理 |
| 官方按键支持多行移动、词移动、选择、撤销及补全 | 完整编辑基本功、提示和终端降级策略 | 保留你的 Ctrl+方向键空间焦点；词移动使用 Alt+方向键，避免冲突 |
| 官方主题用语义 token 区分正文、面板、选择、状态 | 独立颜色 token 和浅色/低色彩降级 | 不直接复制源码组件，不换 OpenTUI；此阶段不提出框架迁移 |

参考：[TUI](https://opencode.ai/docs/tui/)、[快捷键](https://opencode.ai/docs/keybinds/)、[主题](https://opencode.ai/docs/themes/)。源码：[Prompt](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/tui/src/component/prompt/index.tsx)、[Session](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/tui/src/routes/session/index.tsx)、[Theme](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/tui/src/theme/assets/opencode.json)。

## 布局与视觉规格

### 三栏与尺寸

保留当前断点，避免在此次视觉重做中凭空改变既定结构：

| 终端宽度 | 左栏 | 中栏 | 右栏 |
|---|---:|---:|---:|
| ≥140 | 24 | 剩余；160 时为 96 | 40，默认空白 |
| 100–139 | 24 | 剩余 | 隐藏；后续打开对象以中栏阅读模式显示 |
| 40–99 | 按需切至会话列表 | 常态单区 | 后续对象阅读与对话共用单区，有明确返回 |
| <40 或高<12 | 过小提示 | 保留草稿与安全退出 | 不渲染隐藏点击区 |

宽屏左右背景同色，中间比两侧略深；通过背景边界区分，不画外框或三条彩色分隔。中栏左右各两格外边距。标题占两行：第一行空，第二行标题/状态；正文从第五行起。消息文本与 Composer 文本统一从中栏第六格起，工具与列表沿同一起线。

用户消息上下各一行内边距；普通段落间一空行；一次用户 turn 与下一次两空行。短历史顶对齐，溢出后才跟随尾部。无内容时在中栏上半部仅放一条提问和一条辅助文案；Composer 始终在底部，避免发送时搬家。

### 颜色与文字

| Token | 默认深色 | 使用 |
|---|---|---|
| canvas | #101010 | 中栏底色 |
| panel | #141414 | 左右栏 |
| element | #1e1e1e | 输入、用户消息、代码区 |
| selected | #282828 | 当前会话或菜单项 |
| text | #eeeeee | 正文 |
| muted | #969696 | 可读的辅助文字 |
| focus | #fab283 | 当前交互目标的小标记 |
| success | #7fd88f | 必须明确表达的成功 |
| danger | #e06c75 | 错误及必须处理的失败 |

强调色只出现于少数焦点和待处理点，不把所有工具染色。活动不用永久动画填满整屏。颜色不能单独承担语义：同时有 Working、Needs setup、Failed 文本。粗体仅用于标题和当前选中主项。浅色主题后续以语义映射实现并验收，不把这份深色稿称为已完成浅色设计。

### 会话列表

标题与短状态两行一项，项之间一行空白；不放卡片外框、时间戳和第三行说明。标题按 grapheme 截断为省略号，状态保留。当前会话浅底；键盘焦点额外显示左侧暖色标记。鼠标悬停只轻微提亮，不能触发选中。

方向键移动候选项，Enter 打开；点击立即打开。候选与当前 Session 分开，避免读列表时每按一次键都切换运行上下文。滚轮只移动列表视窗。打开后回 Composer；关闭窄屏列表也回到原焦点。当前条目即使滚出屏幕仍保持选中事实。后台消息只更新短状态或未读，不重排正在浏览的列表。

### Composer

整体高度 = 可见文字行数 + 三行结构 + 一行外部提示，默认五行。文字可见行数从 1 增长至 min(8, floor(终端高/3))，并保证正文至少四行；40×12 下上限降为两行。达到上限后只滚动编辑内容，光标始终可见。

最上面一行内边距；编辑区；模型/动作行；底部留白。外侧最后一行右对齐换行与命令提示。80 列保留模型、发送和命令；40 列只保留最短模型提示与 / commands，发送的 Enter 在 /help 中可查。实际动作宽度先分配，模型名尾部省略，禁止相互覆盖。

无模型显示可点击的 `Choose model · /model`，点击与命令走同一选择器。没有 Session 时允许直接写要求，首次发送以稳定请求身份创建再提交；这是对当前“必须 /new”行为的提议变更。失败或响应不确定时保持原草稿与身份，不自动新建第二个 Session。

## 交互状态与操作闭环

### 焦点和键鼠

| 场景 | 键盘 | 鼠标 / 可见反馈 |
|---|---|---|
| 空间移动 | 保留 Ctrl+方向键；左=Session，上=对话，下=Composer；右栏启用后向右进入 | 点击对应区域；仅当前区域的小标记/游标强调 |
| 多行编辑 | ↑↓ 视觉行移动并保留首选列；←→ grapheme；Home/End 行首尾；Alt+←→ 词移动 | 点击定位；拖动选择；越过边界不误触发送 |
| 换行/发送 | Enter 发送；Shift+Enter、Alt+Enter 换行；Ctrl+J 作为可配置降级 | `enter send` 与 `esc stop` 文本为可点击目标 |
| 选择/撤销 | Shift+方向键选择；Ctrl+Z 撤销编辑、Ctrl+Y 重做（编辑区消耗按键，不挂起进程） | 选择仅属于当前编辑缓冲；不共享全局撤销栈 |
| slash | / 过滤；↑↓ 选择；Tab 补全；Enter 选择；Esc 关闭并保留输入 | 点击菜单项，hover 不执行；需要参数的命令补入输入框 |
| 阅读对话 | PageUp/Down 可在 Composer 焦点下阅读而不丢光标；对话焦点的 ↑↓ 按行滚 | 滚轮按所在面板；选中文字不激活链接；回到底部有可见入口 |
| 打开对象 | 聚焦工具/Job 后 Enter；Esc 返回 | 点击有 `›` 的摘要，右栏出现；空右栏无任何事件 |
| 退出 | 保留 Ctrl+Q/Ctrl+C 安全退出；菜单说明 | /quit 使用同一退出路径，保留普通草稿 |

Ctrl+方向键可能被 OS/终端拦截。提供可配置替代和命令入口，但不擅自替换你的空间移动习惯。实现验收必须测试支持扩展键盘协议与不支持的终端；不能只断言按键映射存在。

### Esc 优先级

菜单关闭 → 详情阅读返回/取消选区 → 有工作时停止 → 无工作时无动作。停止只作用于当前 Session，用户看见 `Stopping…` 后等待 App 确认；没有确认前不写 Stopped。关闭菜单和详情永远不能同时停止 Agent。

### 输入生命周期

编辑 → 提交中（对应版本暂存，用户可继续写）→ 已保存/等待执行 → Working → 完成、需回答或失败。Submit receipt 只表示已保存；JobFinished 也不代表整个输入完成。UI 的结束状态来自 InputFinished 或 App 明确投影。

等待配置：保留提交历史，展示“已保存，尚未执行”，提供 /model 或 /connect；配置保存与实际应用成功分别反馈。已保存输入只按 App 队列/重试语义恢复，UI 不重新 submit。

失败：在关联内容下显示两行摘要与展开入口；不把完整错误塞标题。提交响应不确定显示“确认提交结果”，复用 request ID。等待回答：显示实际问题与“回复此问题”上下文，提交绑定 QuestionId；过期问题提示已失效并保留文字。

阅读旧内容：新消息增加未读提示，不跳尾；点击“↓ N new”回到底部。切换 Session 保留每个会话的草稿、光标、选区及阅读锚点。resize 按内容锚点重排，不能只保留旧像素/旧行号。

### 右栏

默认始终空白，保持这次三栏约定。后续第一个启用对象建议是 Job：App 已有 goal、scope、done_when、state、report；无需先做复杂 Git 或架构图系统。

对象页顶端只有类型与关闭，正文是标题、状态、目标、完成条件、范围及相关输入。一次只深入一个对象，不做多个详情 tab。选择另一个对象替换内容；Esc/关闭恢复原来的摘要焦点。随 Session 切换的右栏选择按 Session 保存；迟到详情不覆盖新对象。

140 列以下打开对象时，在中栏进入临时阅读模式，顶端有“← Back to conversation”；草稿仍在状态中，返回后光标复原。右栏内容尚未接线时不能显示无效的 `›`。

Git 后续作为 Workspace 对象，明确相对 HEAD 的基线与“整个工作区”归属，不能声称某 Job 修改了所有文件。架构图和材料树需要先明确 App 投影能力，不在第一阶段假造。

## 能力与实施边界

| 交互 | 当前能力 | 要补的工作 |
|---|---|---|
| 字体层级、背景、对齐、自适应 Composer | renderer 与布局可承载 | TUI 直接重做，不改 Core |
| Markdown、选区、光标、菜单、局部滚动 | 有基础 wrapping/grapheme | 重做编辑和排版缓存，保留真实视觉行 metrics |
| 首次发送自动创建 | App 幂等 create + submit 已有 | TUI 串起两步，各自保持请求身份和失败状态 |
| 模型/配置/登录 | profiles、resolved_config、update_config、login、set_api_key 已有 | TUI 加 slash 选择器及状态；密钥仍交 App；不是设置页 |
| 回答问题 | SubmitInput::answer 已有 | 选中问题与 QuestionId、失效反馈 |
| Job 详情 | SessionView.jobs 已有 | 对象选择、呈现、分页/缓存约束 |
| 成果和证据 | results、result_artifact、result_evidence、evidence_source 已有 | 接对象阅读器，不推断验收 |
| Git 文件 diff | workspace_changes / workspace_file_page 已有 | 保留基线，分页读，内容变化时明确刷新 |
| token 级正文流 | 当前公开 SessionEvent::Reply 提供完整文字 | 第一阶段不承诺逐 token 流式回复；需要时单独设计 App 增量协议 |
| 活动用时、模型消耗、完整工具现场 | 公开投影不保证全部存在 | 不画无来源计时器/花费；只展示已有事实 |

### 实施阶段

A. 视觉基础与输入，先做到每天能用：颜色、三栏起线、标题、消息、Markdown、自适应输入、上下/选区/撤销、点击定位、菜单完整可达。保留原有 App-only、请求身份、草稿保护、分页和终端恢复。

B. 状态闭环：首次发送、配置/登录入口、等待原因、提交失败、回答问题、停止与返回优先级。用真实 App 在隔离目录跑通；mock 只能用来覆盖不可控状态。

C. 右栏第一个真实对象：Job 摘要 → 详情 → 返回，宽窄屏同一对象状态。再按需要接成果/证据/Git；架构图不捆绑交付。

代码落点：`layout.rs` 负责几何和 hit map；`view/` 拆明确组件；`state/` 维护 editor、selection、overlay、对象身份；`run/input.rs` 只解释终端事件；`run/runtime.rs` 接 App。不要在 renderer 读取文件，也不要借重做 UI 重写 Core。

### 验收方式

1. 固定 160×40、140×30、120×30、100×24、80×24、40×12 与断点前后一列；对比同一内容的设计稿和真实截图。终端不可变字号，不用截图缩小来掩盖溢出。
2. 用键盘和鼠标各走一遍：首次输入 → 创建 → 提交 → 继续编辑 → 切会话 → 返回 → 读旧消息 → 收到新消息 → 回尾部。
3. 多行中文、组合字符、ZWJ emoji、长路径，验证视觉光标、点击和选择；菜单在40×12下可到达最后一项。
4. 无模型、登录过期、提交回执丢失、迟到旧快照、停止中和问题失效，检查文案与持久事实一致。
