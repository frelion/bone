# 三栏区域实现与验证

2026-09-11，已实施本轮获准的区域方案。

- 黑底统一为 #090909；两条静态 #505050 单格竖界位于宽屏 x31/x120，最后绘制，面板不能擦掉栏界。较窄窗口只绘制实际存在的分隔。
- 会话条目间留一行真空隙，不触发会话打开；选中标题一行中性底色、细橘标记。当前会话不在左侧重复 Working。
- 用户消息 #191919、输入 #222222；模型移至输入内部底行，快捷键在外侧。草稿上下留白，面板打开时无底层光标、选择高亮或操作提示。
- 命令、模型及连接类型选中项使用橘黄底深字；模型与管理接入分组，分组行不可点击；连接表单取消重复箭头与整行棕底。
- 右侧标题顶部留一行，与主会话标题同基线；正文内缩三格。保留真实对象字段与现有阅读缓存，不增加展示用假字段。
- 40×12 去掉屏幕底部额外空行，腾出第二个输入视觉行，修复光标落在自动换行末尾时整条草稿不可见的问题。

验证：`cargo test -p bone-tui --all-targets --locked` 154 通过、3 个既有性能测试忽略；随后新增精确满行窄屏回归单独运行 1 通过，共155。`cargo clippy -p bone-tui --all-targets --locked -- -D warnings`、构建、格式和 diff 检查通过。

真实 PTY 通过公开UI走查命令菜单 → 模型 → 添加接入 → API表单 → 返回草稿 → 缩放 → 保存退出，没有提交凭据或发送模型请求。最终 verified-40/verified-models/verified-exit 含最终 binary SHA256；退出码0。

证据：`actual/final-160`、`final-120`、`final-80` 为稳定重绘帧；`actual/verified-40` 为修复后的最小尺寸；`verified-models` 为最终模型菜单。早期08-two-columns和final-40记录了过渡旧帧/修复前问题，不能用作验收通过证据。

`production-160.svg` / `production.jpg` 是合成会话经过生产 Ratatui 渲染器的预览；`actual/*.svg` 是实际PTY字符与颜色的重建，不是原生终端截图。SVG字体行高会让│出现细小接缝；PTY已验证分隔每行连续存在，但没有证明所有终端字体的原生字形无接缝。

本轮没有改变模型接入能力，也没有验证真实远端LLM调用。

## 后续光标调整

输入框移除 `›`，光标使用橘色原生块光标。输入、粘贴、光标操作及窗口缩放后保持常亮，闲置700ms后启用终端原生闪烁；不叠加软件光标，也不通过重绘整屏模拟闪烁。退出重置光标形状与颜色。

后台草稿保存和概览请求的调度不再无条件将画面标为dirty，避免每500ms重发光标显示指令。原有未绘制的dirty状态仍保留，保存结果等真正的状态变化仍能触发绘制。PTY回归覆盖闲置→闪烁、连续输入→常亮、停手→恢复闪烁及退出恢复；原生终端实际闪烁周期由用户的终端控制。
