# BONE 区域与层级方案 · 2026-09-11

这是待用户评审的设计方案，不是已实现效果。生产代码未在本轮修改。图中会话、模型和执行情况为合成示例；不代表真实授权或验证结果。

## 设计目标

一眼分清左侧选择会话、中间阅读与输入、右侧阅读对象。保留用户确定的三栏、32 格左栏、黑色与橘黄、细选择标记、输入上下留白及消息同宽。以一致的区域和组件规则提高完成度，不复制 OpenCode 品牌造型。

## 推荐结构

160×40 时左栏 0–31、中栏 32–119、右栏 120–159。中性细界位于 x31 和 x120，贯穿高度，没有顶底横框和交角。占用现有边缘留白，左栏仍 32 格。边界不随焦点变橙，也不是新的可点击控件。

首选统一 #090909 黑底加细界，以减少大面积灰色斑块；原底色加细界作为更保守的对照。细界候选 #505050，需在真实终端与 #303030/#404040 比较后确定。不能把候选色值写成已经验证的最优答案。

左栏是选择区：项目名、新建入口、会话列表分组。选中行中性浅底 + 橘黄细标记；状态属于会话条目，标题与状态紧邻，条目之间留空。当前会话不再重复运行进度；后台会话需要用户处理时突出提示。长列表按可用高度自然滚动，不固定每项四行。

中栏是阅读区：标题与回复同阅读轴；用户消息、菜单与输入共享 x36、宽80 的表面外沿。正文白、说明灰，代码局部紫/青。用户消息底色比输入更暗。工具结果按紧凑行呈现，避免每条工具生成灰色大卡片。

右栏是对象区：空时保留栏界，不增加占位内容。打开对象后标题与来源对应，状态紧接标题；范围、完成条件、结果等使用标签和值的紧邻分组，组间一行空白。内容按实际对象类型提供，不能虚构字段来填满版面。

## 输入与面板

两行草稿示例：上留白一行、草稿两行、下留白一行、模型元信息一行；外部快捷键独立一行，避免模型名称与三种动作挤在一条状态栏。单行草稿相应缩短。保留实心块光标。

菜单仍锚定输入上方，与输入同宽。标题和 Esc 同行；模型、管理接入分组。唯一 slash 入口仍是 /model。选中候选使用橘黄底和黑字；“当前模型”另用文字说明，不能让选中候选与当前配置混为一谈。示例模型列表不代表真实可用模型。

表单建议固定字段标签列，字段之间保留适量间距，当前编辑字段用局部焦点与块光标，不用整行暗棕底冒充菜单候选。只显示当前面板的操作提示；底层草稿保留但不显示可编辑光标。本轮图覆盖对话、空右栏和模型菜单，表单尚未提供独立视觉稿，不声称完整覆盖全部状态。

## 实施前与实施后的验收

1. 在同一内容下比较 tone/tone-line、flat/line，确认区域感来自边界而非偷偷改变内容。
2. 右栏为空时仍能看清三栏；详情与模型菜单仅有一处操作归属。
3. 真实终端检验竖线连续性、线与正文的主次关系；SVG 并不能证明 box-drawing 无接缝。
4. 120、80、40 列继续采用现有隐藏/单区域规则；只为存在的栏画边界，不缩小字号或压窄左栏。本轮未画这些窄屏，不声称验证完成。
5. 实施时重验光标、命中区域、滚动、长模型名、中文折行、面板返回与草稿保留；视觉改动不能破坏已有交互。
