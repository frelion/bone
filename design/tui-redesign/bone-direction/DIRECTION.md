# BONE · 独立视觉方向

2026-09-10，待评审。本轮只修改设计材料，不改产品代码。此文件替代上一版 PLAN.md 的颜色、输入区、焦点视觉和消息间距规格；请求身份、App-only、编辑、分页和持久化要求继续有效。

## 核心决定

BONE 是一张有明确阅读次序的工作案头：左栏选会话，中栏提出问题与形成结论，右栏查一个具体对象。辨识度来自对齐、持续的空间关系和清楚的阅读层级。

保留三栏 24 / 剩余 / 40，140 与100列断点不变。右栏默认空白；不加概览、统计或占位文案。去掉上一版 OpenCode 式暖橙＋粗侧线的输入外形。

## 与上一版及 OpenCode 的区别

| 维度 | 上一版 / 本次参考证据 | 新方向 |
|---|---|---|
| 输入轮廓 | 上一版采用暖橙粗左线，接近本机 OpenCode 空态 | 用水平分隔确定编辑区起点，浅底承载正文，不画侧框或装饰角 |
| 主色关系 | 上一版几乎沿用 OpenCode 默认黑灰和暖橙 | 石墨灰、骨白正文、低饱和冷青焦点；状态用文字说明 |
| 标题与栏间关系 | 各栏标题缺少统一基线 | 中栏与有内容的右栏在同一行显示对象标题，下一条水平线标明阅读区域 |
| 焦点 | 上一版橙色侧线容易与 Agent/消息身份混淆 | 当前区域的水平线提亮；左栏焦点用同色的候选强调；对象选择用浅底，不用颜色模拟连线 |
| 消息 | 原稿大量暖色代码与工具箭头 | 骨白为主，代码主要靠缩进和浅底；工具过程是安静记录，可打开的 Job 才用 [+] |
| 产品识别 | 容易首先联想到 OpenCode 输入框 | 三栏同名对象联动、连续文档式阅读、水平编辑区共同形成 BONE 特征 |

OpenCode 来源沿用上一轮的实机与固定 SHA 研究，不声称本轮重新运行了它。参考 [官方 TUI](https://opencode.ai/docs/tui/) 与 [固定版本 Prompt 源码](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/tui/src/component/prompt/index.tsx)。这次对“相似感”的判断属于设计判断，不是测量出的品牌识别结论。

## 视觉规格

| Token | 色值 | 用途 |
|---|---|---|
| canvas | #171b1c | 中栏石墨底 |
| panel | #131718 | 左右栏 |
| element | #1d2324 | 用户输入、编辑区、代码 |
| selection | #263234 | 选择的会话或对象 |
| text | #e5e2d9 | 骨白正文 |
| muted | #a1aaa8 | 辅助文字，仍须清楚可读 |
| divider | #3c4748 | 无焦点水平线 |
| focus | #94b9b3 | 当前阅读/编辑区域的水平线及少量入口 |
| success / error | #aab9a1 / #d6a09a | 必须强调的结果，配合文字 |

同一终端字号，ASCII一格、中文两格，14px字、9×20px字符格。所有结构都是终端能实现的整行、整格；无阴影、圆角、渐变、字体大小层级和像素细线。水平线使用终端 box-drawing 字符。实现时具体字号与字格由用户终端决定，稿件数字仅是查看比例。

左侧 BONE 是局部品牌标记，不形成全屏品牌栏。中右栏标题在第2行，水平线在第4行；中栏左右各3格边距，正文与编辑文本统一从第6格开始。用户消息保持原约定的低对比底色与细竖线，这条线属于已发送消息，不属于编辑控件。

输入区起点是单条水平线，下一行开始浅底，正文上下留一行。模型和发送/停止放在浅底外的同一行；命令提示在最后一行。输入框高度按文字增长，保留原方案的上限与正文最小空间；40×12时压缩为单行编辑视窗。大屏不放常驻快捷键大全。

语法色可在实现中使用少量低饱和色，但不能把代码整体染为焦点色。正文段落之间一空行；主题/工具组之间可两行，避免每句话都被拆成松散卡片。

## 三栏联动：可评审状态序列

1. 常态对话：左侧当前会话浅底，中间输入拥有焦点，右侧空白。
2. 打开对象：点击正文 `[+] Draft recovery`，或在对话对象上按 Enter。正文原位高亮，右栏同名标题出现；只看对象，不发起产品写操作。
3. 右栏焦点：右栏水平线提亮，Composer 分隔线恢复中性，光标隐藏。中栏保留所选对象的浅底，用户能回看来源。
4. 返回：右栏 `esc back` 与鼠标返回目标触发同一动作，关闭右栏内容并恢复来源对象焦点；再 Ctrl+Down 回输入，恢复光标与草稿。
5. 切换会话：三个区域一同切到新 Session 的本地视图；迟到详情不覆盖新对象。对象失效时显示解释和返回，不跳到另一个对象。

未实现 Job 接线时不显示 [+] 伪入口。右栏详情仍是阶段C功能，不因为画进设计稿就当成产品已有。正文工具行只是过程记录，完整输出可打开能力尚未接线时不做可点击外观。

宽度小于140时，对象改为中栏临时阅读模式，标题包含 `Back to conversation`，退出后恢复草稿。单区会话入口经 /sessions 可达。40列不塞对象双栏或完整模型名。

## 保留的交互基础

- Ctrl+方向键空间移动；Alt+方向键词移动；编辑↑↓按视觉行移动，点击定位按 grapheme。
- Enter发送，Alt/Shift+Enter换行；粘贴不执行；提交中继续编辑，回执只清匹配版本。
- slash菜单锚定输入上方，固定命令列，方向键选择，Tab补全，Esc关闭不停止工作。菜单顶部线中性，选中项用浅底与字重，不添加多色类别。
- Esc先退出当前局部操作，再考虑停止；对象返回、菜单关闭、取消回复关联不能误停任务。
- 已保存、未执行、Working、Needs you、Stopping分别呈现；当前主稿为Working，因此会话、标题、Job与停止提示一致。
- 阅读旧历史时新消息不跳尾；回到最新入口仍可见。默认右栏空白无需解释性标签。
