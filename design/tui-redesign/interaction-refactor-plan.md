**BONE 交互层重构方案 · 多 agent 对抗讨论定稿**

状态：已完成实现、独立对抗 review、测试与 release 安装。2026-09-16。

目标：让工作区内容、键盘归属、鼠标操作各自有明确边界。右栏详情属于工作区；鼠标操作不请求获取键盘焦点。直接替换现有交互模型，不保留兼容层、旧接口别名、旧状态双写或旧行为开关。

**一、产品规则**

1. 键盘焦点表示输入角色/作用域。鼠标切换会话时，Composer 仍是 Composer，编辑的会话内容随选择变化。
2. 鼠标可以查看、选择、提交、滚动和拖拽，但不能请求另一个键盘目标获得焦点。
3. 详情阅读器永不属于键盘目标。打开、刷新、关闭详情不改变键盘归属。
4. 浮层可见与浮层拥有键盘是两件事。鼠标打开只展示；明确的键盘操作才进入浮层。
5. 当前键盘目标被关闭或移除时，必须在该生命周期操作中恢复有效目标。这是明确的例外：关闭拥有键盘的浮层恢复进入前的工作区角色；所选会话消失导致标题编辑目标不存在时回到 Composer。不增加每帧猜测焦点的 normalize 函数。
6. 鼠标点击已聚焦编辑器可以定位和拖选。点击未聚焦编辑器不激活它。表单内部字段通过键盘切换。
7. 点击、滚动分别命中；按钮或链接不会吞掉所在区域的滚轮。
8. 浮层只遮挡自身矩形范围。矩形内的空白也不会穿透；矩形外的工作区照常操作。
9. hover、滚动、异步刷新不会中断编辑撤销分组，也不会顺手终止拖拽。
10. 接收文字的输入区必须可见。窗口过小无法显示时暂停普通编辑与粘贴，保留键盘归属，显示尺寸提示；保留退出等全局操作。

**二、状态模型：只保留四个独立概念**

下面为类型草案，保留现有会话、编辑器、请求关联及布局宽度等状态，不借机重写业务层。

```rust
struct UiState {
    keyboard: KeyboardOwner,
    details: Option<ReaderState>,
    overlay: Option<Overlay>,
    pointer: PointerState,
    // Existing session, editor, request and layout state.
}

enum KeyboardOwner {
    Workspace(WorkspaceTarget),
    Overlay { return_to: WorkspaceTarget },
}

enum WorkspaceTarget {
    Sessions,
    SessionTitle,
    Composer,
}

enum Overlay {
    Objects(ObjectPanel),
    Models(ModelPanel),
    Help,
}

struct PointerState {
    position: Option<Position>,
    capture: Option<PointerCapture>,
}

enum PointerCapture {
    Divider(PaneDivider),
    Editor(EditorTarget),
}
```

`keyboard` 是唯一活动键盘归属。`return_to` 只记录返回位置；现有的中栏导航记忆也只用于返回，不参与推导当前焦点。光标、选区、撤销历史继续属于编辑器，当前表单字段继续属于表单，不把所有内部字段提升为全局状态。

`PointerCapture::Editor` 只用于当前活动编辑器的拖选。捕获期间若编辑对象因会话/输入上下文切换而被替换，或键盘切换输入作用域/活动表单字段，在该切换操作中结束旧编辑器捕获，不继续修改已不活动的编辑器，也不把后续拖选应用到另一个文档。普通字符输入保留捕获；分栏捕获不受键盘目标切换影响。

右栏内容有明确的所属会话。切换到另一个会话时关闭旧详情；不新建每会话详情缓存。属于旧会话的浮层也在切换时清理。保留现有草稿与编辑位置，以及旧标题提交流程。

**三、命中模型：一个工作区、最多一个浮层，两种查询**

```rust
struct SurfaceHits {
    clicks: Vec<ClickRegion>,
    scrolls: Vec<ScrollRegion>,
}

struct FrameHits {
    workspace: SurfaceHits,
    overlay: Option<(Rect, SurfaceHits)>,
}
```

只用现有矩形命中与倒序查找。先选表面，再选事件对应的区域：

- 坐标在浮层矩形内，只查浮层；没有匹配也停止，不向工作区穿透。
- 坐标在浮层外，查工作区。
- 点击查询 clicks；滚轮查询 scrolls。
- hover 从当前帧的 click region 派生；必要时给 region 一个简单视觉角色，如 Button、Row、Divider。
- 分栏和编辑器拖选从点击命中开始；捕获建立后，Drag/Up 优先路由给捕获目标，不再查询指针当前位于哪个表面。

不建立第三套 hover 列表，不建立独立 drag 命中图，不增加控件树、事件冒泡、父节点链或可配置事件策略框架。

根渲染器拥有最终合成权。子组件只能登记自身区域，不能清空全局命中图。分栏边界属于工作区；浮层实际覆盖边界的部分不可抓取，未覆盖的部分可抓取，已捕获的拖拽可以跨越浮层继续。

slash 建议列表占用同一个浮层展示槽，不引入浮层栈。它的查询由 Composer 草稿派生，键盘仍归 Composer；显式浮层显示时不同时叠出命令建议，但键盘入口仍可解析 Composer 中完整的命令。

**四、事件与动作边界**

键盘事件：根据唯一 KeyboardOwner 解释，产生明确的编辑、导航、业务或进入浮层意图。

鼠标事件：先处理已有捕获，再按当前帧选择表面和点击/滚动目标，产生内容操作或更新鼠标短暂状态。

异步业务结果：继续走现有 reducer/Effect 流程，按 session/request/generation 更新内容；不得因回包完成而主动取得键盘。

具体约束：

- 消息提交函数只提交文本，不解析 slash，也不猜测输入来源。
- 展示详情不提交标题、不切换焦点、不重置鼠标捕获。
- 打开浮层与进入浮层分开；键盘入口在打开成功后进入。打开失败保持原键盘目标。
- 不为每种浮层造一对 OpenX / OpenXAndFocus，不增加 ActionBatch、命令脚本或通用事务执行器。组合在具体 UI 命令入口完成。
- 标题提交属于明确离开标题编辑或切换会话的生命周期；不由通用业务动作前置逻辑猜测。
- 光标重置只由实际编辑/键盘导航等相关操作触发；hover 不重置光标计时。
- 编辑器自己维护连续输入与撤销分组；不再在所有非输入 Action 前调用 break_interaction。
- 拖拽由 Down、Drag、Up 及明确的取消事件维护。Esc、终端失焦、窗口尺寸变化或捕获目标失效可取消；普通键盘输入、滚轮和异步刷新不会取消。

鼠标位置更新需要使相关视图重绘，但不经过带业务公共副作用的动作入口。渲染后保存的 FrameSnapshot 仍是鼠标几何依据；不要在输入层重复计算组件布局。

**五、明确收敛 slash 命令交互**

这是有意的产品变更：

- 鼠标点击命令候选只补全/准备 Composer 草稿。
- 命令由 Composer 中的键盘 Enter 执行。
- 命令模式的发送位置显示执行提示，不保留鼠标执行命令的按钮。
- Composer 拥有键盘时提示“Enter 执行”；其他目标拥有键盘时提示先通过对应现有快捷键回到输入区，不展示错误提示。
- 普通文本仍然可以点击发送。
- 独立的模型按钮仍可用鼠标打开模型浮层，只展示、不接管键盘。

将现有纯命令解析移到输入/命令入口。鼠标候选动作只编辑草稿；键盘入口解析命令并执行具体 UI/业务意图。因此无需把 pointer bool 从 submit 传到 execute_command 和其他业务函数，也无需保留 ClickSubmit 与 Submit 两种来源动作。

代价是命令候选不再单击立即执行；所有命令仍然可达，换取统一交互和明确的来源边界。不提供旧行为开关。

**六、布局及生命周期规则**

| 场景 | 确定行为 |
| --- | --- |
| 宽屏展开详情 | 显示在右栏，保留左右分栏拖拽及各区域滚轮。 |
| 没有右栏的窄屏 | 详情替换消息正文，保留标题与 Composer；关闭后恢复消息正文。 |
| 鼠标打开浮层 | 浮层避让仍接收文字的编辑区域；可用空间不足时内部滚动。 |
| 浮层当前拥有键盘 | 浮层活动输入区域保持可见；F6 返回工作区时重新布局以露出返回目标。 |
| 鼠标关闭拥有键盘的浮层 | 在关闭操作中恢复 return_to；若标题目标已不存在，回到 Composer。 |
| 鼠标切换浮层页面 | 属于同一 Overlay 输入作用域中的内容切换；新页初始化局部导航状态。已有表单内点击另一字段不能改字段焦点。 |
| 异步加载/登录完成 | 更新数据和状态，不自动进入新的密钥输入界面。 |
| 鼠标切换会话 | 保存旧草稿、提交旧标题，切换内容；保留工作区输入角色。清理旧会话所属的详情与浮层，必要时执行目标销毁恢复。 |
| 窗口过小 | 暂停普通编辑与粘贴，保留输入归属；恢复尺寸后继续。 |

布局规则归 LayoutPlan，组件不自行决定覆盖 Composer 或删除其他区域的交互。显示位置改变不等于输入角色改变。

**七、hover 的落点**

- 可点击条目：轻微中性背景提亮，保留原有语义文字颜色。
- 分栏边界：悬停时提高对比度，拖拽状态更明显。
- 普通正文：不伪装成按钮，不做整栏高亮。
- hover 不使用表示当前会话或键盘光标的强调色，也不更新业务选中项。
- 鼠标不动而内容滚动、布局变化时，按新帧重新计算 hover，不缓存旧 Action。

**八、保留与删除**

保留：LayoutPlan、FrameSnapshot、现有编辑器、reader 内容投影、会话草稿机制、reducer/Effect、现有异步关联校验。

删除并直接替换：

- Panel::Reader 以及通过 panel 是否存在控制整个工作区的规则。
- panel_keyboard、panel_has_keyboard 及多处联合推导键盘归属的代码。
- UiEvent::PointerAction(Action)、提交/命令链中的 pointer bool、ClickSubmit。
- 子渲染器的全局 hits.clear 权限。
- 单个 HitTarget 同时代表点击和滚轮归属的接口。
- handle_action 对无关动作统一提交标题、重置 caret、打断编辑或取消拖拽的前置逻辑。
- 旧交互契约中的全局鼠标独占断言及相关失效测试。

不保留旧 API alias、兼容 wrapper、双状态、旧行为 feature flag。已有请求与世代校验保留，它们保障异步正确性，不是兼容负担。

**九、实施顺序与完成标准**

1. 替换键盘归属与展示状态，拆出详情，收敛生命周期与命令入口；删除对应旧路径。
2. 替换 FrameSnapshot 中的命中接口，根视图统一组合表面；点击与滚轮分离，捕获独立。
3. 将窄屏详情、浮层避让与尺寸不足规则收回 LayoutPlan；组件消费明确区域。
4. 加入 hover，清理公共副作用，替换旧测试契约。
5. 独立 agent 对抗 review 完整差异，跑全工作区检查，再构建 release 并替换安装二进制。

这些步骤是同一次重构的工作顺序，中间不保留两套可切换架构，也不交付只修一半的版本。

验收以真实事件经过布局、命中、输入、状态更新的连续操作链为主：

- 建立中栏选区 → 点击真实工具结果展开详情 → 滚轮经过按钮与正文 → 左中右分别滚动 → 拖动两条分栏 → 继续输入，验证编辑目标、选区替换及草稿正确。
- 鼠标打开模型浮层 → 中栏继续输入且可见 → F6 进入浮层 → 表单字段键盘切换 → 点击非活动字段 → 输入不落错字段 → 鼠标关闭 → 恢复原目标。
- 分栏/编辑器拖拽 → 接收普通键盘输入或异步更新 → 指针跨表面 → 松开；验证捕获在明确生命周期结束前持续有效。
- 详情展开 → 宽屏变窄屏 → TooSmall → 恢复宽屏，验证没有隐形输入或意外切焦点。
- 鼠标补全 slash → Enter 执行；普通消息按钮仍可发送；打开失败不改变键盘目标。
- hover 移入/移出、鼠标静止时滚动与重排，验证样式对应当前帧且不影响撤销与光标计时。

全工作区 fmt、Clippy（warnings 为错误）、测试和文档测试通过后，再做实际终端的鼠标操作验收。单元测试数量不作为完整交互正确性的替代指标。

**十、多 agent 对抗讨论记录**

| 争议 | 反方指出的问题 | 最终决定 |
| --- | --- | --- |
| 三套点击/滚动/hover 列表 | 职责不同不代表需要三份区域数据，增加维护一致性成本。 | 只保留点击与滚动；hover 派生、drag 捕获。 |
| 鼠标绝对不能改变任何焦点状态 | 关闭当前键盘浮层后会留下不存在的输入目标。 | 禁止鼠标获取焦点；目标销毁时明确恢复原有效角色。 |
| 把鼠标坐标下所有事件直接查同一列表 | 子按钮吞掉所属区域滚轮；独立列表缺少遮挡边界仍会穿透。 | 先选表面，再按点击/滚动查询。 |
| 窄屏只隐藏被遮挡的光标 | 用户仍可能在看不见的输入区写入。 | 保留活动编辑区可见；尺寸实在不足暂停普通输入。 |
| slash 保留鼠标立即执行 | 来源或附加焦点意图仍需在入口处理，导航命令容易出现不同语义。 | 明确改变交互：点击补全，Enter 执行；命令态发送提示同步改变。反方确认此完整前提下无功能不可达。 |
| 重建通用事件/焦点框架 | 没有必要的使用场景，会扩大重构范围。 | 一份键盘归属、一个工作区与一个浮层、两种矩形查询、一个捕获状态。 |
