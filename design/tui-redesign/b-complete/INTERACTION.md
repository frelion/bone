# B 完整设计：交互与实施规格

2026-09-10。用户已选择B视觉方向，本文件保持局部输入表面、开放代码、连续多轮阅读；不改回全中栏停靠输入。不修改产品代码。各状态仍待真实界面实现与验收。

## 1. 不能被状态页破坏的B结构

左24列为会话标题+短状态，当前选择用浅底；中间只有局部标题、连续历史和局部Composer；右40列默认纯空白，没有空态文案、焦点或点击目标。160列中栏96，正文主要72–78格阅读轴，用户消息和输入面略向外延伸。代码直接在正文里按缩进、语言提示和轻语法色展示，不升级为与输入竞争的大卡片。

输入表面从中栏边界内缩：160/120时左右各4格以上，80时各3格，40时各2格。状态与局部菜单归这个输入区域；不得增加横跨三栏的动作栏、全局顶栏、设置页或详情tab。交互标记只表达真实可执行动作，没接线的对象不画蓝字、箭头或按钮。

## 2. 输入：一行、多行与编辑焦点

推荐统一几何为可见编辑行数N+3行：上留白1、编辑N、间隔1、单行元信息1。N=1时4行、N=2时5行，不为“继续对话”再加一行标题。元信息同一底行放模型、提交、命令；空间不够时先删换行教学，再缩模型名，保留主要动作。换行教学可在首次空态/帮助展示，不必永久挤满底行。主图与所有状态图应使用同一约定。

- 输入默认N=1，按软换行与显式换行增长。40高最多N=6，30高N=5，24高N=4；小于18高最多N=2。必须同时保证正文至少4行、局部标题最多2行。
- 40×12时默认4行Composer；N最多2，必要时减少内留白成为N+2行，总高不超过4。不得把整张160图缩小；文字仍一个终端字号。
- 达到上限后只滚动输入内容，光标留在可见区域，显示淡色“上方还有输入”指示，不把完整草稿塞成一行省略号。
- `Enter`提交；`Shift+Enter`/`Alt+Enter`换行。不能识别Shift+Enter的终端保留Alt+Enter可用替代；按键帮助写当前实际支持情况。
- `↑↓`按视觉行移动，保留首选列；`←→`按grapheme；Home/End到视觉/逻辑行边界的定义必须统一，这版采用逻辑行首尾；Alt+←→按词。输入首尾不触发历史替换或会话切换。
- Shift+方向选择，Ctrl+Z/Ctrl+Y在编辑区撤销/重做；点击定位、拖动选择按同一grapheme metrics。越过空白只定位最近合法位置。
- 粘贴只插入，包含换行或slash也不直接执行。提示符`›`是非内容，不能被选入提交文本。
- 真实光标只在Composer焦点存在；其他区域焦点时浅底仍在、光标消失，不能仅靠颜色区别“可输入”和“选中正文”。点击整个局部编辑文本区域可定位；元信息的动作另有hit region。

原版已有左右/删除/行首尾和保存草稿基础；上下视觉行、选择、撤销、点击定位、自适应高度为拟实现。

## 3. 提交、追加与停止：实际App语义

### Submit

`Editing(revision) → Submitting(request_id, revision) → Saved(input_id) → Queued / Posting / Accepted / Waiting / Finished`。

普通空白不提交。等待保存回执时可继续写，但同一待提交请求不能因重复Enter生成第二个request_id。成功回执仅清除其匹配的revision与text；用户后来写下的内容不能被清空。当前TUI已有此保护，重做输入必须保留。

Idle显示`enter 发送`；Running显示`enter 追加`。App的`accept_input`先持久化Queued，发送回执后马上`deliver_queued`、调用agent.post；所以不能声称“必等当前任务结束才执行”，也不能叫“立即中断/steer”。实际Queued快照到达时，在那条输入下显示短状态“待处理”；Posting/Accepted后更新状态。输入处不重复展示整张任务队列。

输入只有Receipt不能显示“已完成”。InputFinished与App投影决定输入完成；JobFinished不必等于整个输入结束。

### Stop

当前App `stop()`会取消所有仍Queued的输入，然后停止runtime；并非只停止眼前一个Job。无待处理输入时提示`esc 停止`；存在Queued时提示`esc 停止全部`，局部状态说明“含待处理输入”。点击与按键走同一路径，不额外加确认对话框。

调用后显示“正在停止…”，直到App确认后才显示停止/取消；操作无效或失败明确反馈，不能伪装已停。已取消内容保留历史，允许用户显式“恢复到输入”后重新提交；取消输入当前retry分支不支持恢复，不能把它伪装成原身份retry。若当前草稿不空，“恢复到输入”追加为可撤销编辑，不静默覆盖草稿。

## 4. Slash菜单：局部覆盖层

菜单锚在Composer上方、宽度与局部输入表面一致，覆盖历史而不推动输入上下跳。中栏标题与左栏不变。搜索行与输入草稿是一条query的可见表达，不复制两个可编辑搜索框。

状态：`Closed → Open(query, candidate, scroll) → FillArguments / Execute / Close → ReturnFocus`。

- ↑↓只移动候选，选中项必须滚进视窗；Tab补全，Enter选中。需要参数的命令填回输入并把光标放在参数处；无参数明确动作直接执行。
- 可见6条为常见上限；40×12至少一条可见、全部可滚到。命令名优先，描述按宽度省略；不让不同命令长度推歪描述列。
- Esc只关闭菜单并保留query/草稿；背景停止提示在菜单打开时改成可点击“停止”或隐藏Esc键提示，不能一次Esc同时Stop。
- 无匹配显示“没有匹配命令”，不留空高亮候选；输入改变或清空时重新计算，不把旧index指向新命令。
- 鼠标hover不执行，点击才执行；overlay可见区域阻止点穿到历史对象。

已有命令：/new、/sessions、/rename、/help、/quit。/model、/connect及配置选择器为拟实现，底层App能力存在；不能在“当前已可用”列表里混写。/new仍是创建入口，省略title按App首次输入标题；首次发送自动创建为单独拟变更，不作为这版默认已批准行为。

## 5. 切会话：选择、候选与草稿彼此独立

左栏当前Session用浅底，短态来自App；“当前会话”不是执行状态，不能替代短态。后台需要回答比普通已完成醒目，但刷新不在用户操作中自动重排列表。

进入列表时候选从当前会话开始，↑↓仅浏览候选，Enter打开；点击会话立即打开。滚轮只滚列表，不能一滚就修改实际打开会话。当前实现键盘/滚轮会选择的行为需拆成候选与提交选择，这是拟实现。

每个Session保留`draft + revision + cursor + selection + undo + reading_anchor + selected_object + focus_return`。现有draft/cursor/滚动缓存基础保留，selection/undo/object增加。切换保存原上下文，新会话默认Composer焦点；旧Session异步提交仍按自己的request/generation处理，不修改新编辑缓冲。

窄屏会话选择是单区临时列表，顶端明确“返回对话”；Esc返回进入列表前的焦点。取消浏览不切换Session，不清空草稿。

## 6. 阅读历史与工具输出

短历史从上开始，内容达到视窗后跟随尾部。`FollowingTail`与`ReadingAnchor(message_id, grapheme_offset)`分开：用户向上滚动即进入ReadingAnchor；新的内容增加`↓ 新回复`入口，不强行跳尾。显式回最新才恢复跟随。

普通↑↓在Conversation按行滚，PageUp/Down按视窗，Composer焦点下PageUp/Down也可读历史而保留编辑光标；不能误解释为输入行移动。滚轮按指针所在区域路由，空右栏不滚任何区域。当前实现空右滚轮会落入正文滚动，拟修复。

Resize保存内容锚点而非旧屏幕行号，流式/完整消息追加都如此。缓存淘汰不能跳位置；已有32MiB全局历史预算与分页边界继续保留。

工具按来源成紧凑连续组：读取动作+路径/数量，完成结果+具体事实；用户手动展开后不被快照自动收回。错误默认显示2–4行摘要，再查看全文。自动折叠不得让正在读的旧内容上跳。打开完整工具输出要求App真实投影；不从日志拼工具状态，不露推理内容。

## 7. Question回答：输入的局部上下文

App已有`QuestionId {runtime, record, reply_to}`与`SubmitInput::answer`，TUI尚未接线。

Question正文在其来源位置显示完整问题与“回答此问题”入口；不要把同一问题全文再次放右栏或输入上方。选中回答后Composer上方加一行短关系“回答：<问题摘要>  ×”，保留普通草稿为独立ordinary buffer，打开该Question专属answer buffer。退出回答恢复普通草稿与光标，避免把问题答案混成普通追加。

Enter动作显示“发送回答”，绑定完整QuestionId。提交回执、revision保护同普通输入。切Session时回答缓冲按Session+Question保存；不能把它自动绑定新会话的问题。

问题已解决/过期/runtime更换：保留文字，显示“这个问题已失效”；禁用带旧QuestionId的发送，给“转为普通输入”显式动作。后端拒绝也不能删草稿或自动当普通消息重发。多问题同时可见时只回答用户选的那个，不推测“最新就是目标”。

Esc优先取消局部回答关系、恢复ordinary buffer；只有没有菜单/详情/选区/回答关系时才进入Stop分支。

## 8. 失败、无模型与登录恢复

每个失败依附对应输入/操作呈现短摘要，技术全文进展开阅读，不污染会话标题。

| 情况 | 当前界面事实 | 动作与恢复 |
|---|---|---|
| 未选择模型 | 输入已保存但未执行；左“需要配置” | /model打开局部选择器；配置成功后核对App重新派发/显式retry原InputId，不再次submit |
| 凭据缺失/过期 | 需要登录；文字不丢 | /connect调用App login/API key流程；状态区显示等待/取消/失败，密钥不进入聊天历史 |
| 提交结果不确定 | 保留pending request_id和文本，显示确认保存状态 | 同一request_id重试相同内容；禁止自动生成新身份重复提交 |
| 已保存输入RoutingFailed | 关联输入显示失败原因 | 用Session::retry(InputId)，不是复制文本submit |
| Cancelled/Rejected/Interrupted | 历史真实终态 | 仅在后端支持的状态提供retry，否则显式恢复为草稿；文字可能产生新输入，需要用户主动发送 |
| 对象读取失败 | 右栏/阅读面保留对象名和失败 | 只重试读取该对象，不重新运行任务 |
| stop失败 | 不显示已停止 | 保留当前工作态与简明原因，Stop可再次尝试 |

/model选择只改变配置，不伪造已执行；更新配置时当前工作是否生效由App receipt/projection说明。ProfileBusy等错误要就地说明，不能 silently fallback另一模型。设备登录链接与验证码如果App返回，显示在局部选择器中；任何新外部操作都不绕开App-only边界。

## 9. 对象与焦点返回

第一个可落地对象是Job：App `SessionView.jobs`已有目标、状态、完成条件、报告等；TUI的ObjectReader、选择、加载和返回栈均为拟实现。成果/证据/Git能力另列，不能因为画了详情就认为全都已接。

`Closed → Loading(ObjectRef, session, generation) → Ready / Error / Expired`。160宽在右栏显示；原始摘要浅底保留source selection。焦点移动到右栏时显示右栏标题局部焦点符，Composer光标消失。右栏不靠大色块整面高亮。

Esc/关闭：关闭对象并恢复来源行的Conversation焦点，而不是直接跳Composer。第二次Ctrl+↓或点击输入才回编辑。必须有“详情→来源对象→编辑”的三态图。选择另一个对象替换详情，同时更新return source；旧异步结果因generation不匹配丢弃。

120/80详情占中栏/单区，Composer仅隐藏显示、草稿保留；标题有局部返回；退出恢复阅读锚点和来源焦点。160→120时详情仍打开，把焦点映射到同一阅读器；120→160恢复右栏，不丢对象与滚动位置。不存在多个详情tab或另造Dashboard。

## 10. 160/120/80/40响应式合同

| 尺寸 | 主结构 | 输入 | 菜单/详情 |
|---|---|---|---|
| 160×40 | 左24/中96/右40；右默认空 | 单行4、两行5、最多9行总高，局部内缩 | 菜单锚Composer；详情在右40 |
| 120×30 | 左24/中96，右隐藏 | 最多8行总高；中间文字宽度与160一致 | 详情替换中栏，返回草稿不丢 |
| 80×24 | 单区对话；会话按需切换 | 左右3格，最多7行总高 | 菜单先删描述；对象单区阅读 |
| 40×12 | 最小可用单区 | 左右2格，最多4行总高；模型短名/提交动作优先 | 至少1候选可滚；详情每行自然折行，不能塞表格 |

实际断点≥140三栏，100–139两栏，40–99单区；不是只针对四张图片写特例。<40或高<12显示过小提示，保留草稿和退出。宽度139/140、99/100须有回归。左右滚动隐藏内容不构成响应式方案；长代码可保留专门水平滚动入口，但普通文字必须折行。

## 11. 焦点与Esc总优先级

`Modal/Slash → ObjectReader返回 → 文本选区取消 → Question答复关系取消 → Stop当前Session（含Queued） → 无动作`。一次键只消费一层。当前已经打开的菜单、详情、回答关系通过就地提示解释Esc的实际动作，不在背景仍显示错误的“Esc停止”。

Ctrl+←到列表，Ctrl+↑从Composer到Conversation，Ctrl+↓从Conversation回Composer，Ctrl+→从Conversation进入已打开右栏；右栏为空无焦点。保留项目既有空间方向习惯，OS/终端拦截时提供配置替代与slash入口。普通Tab不承担全局焦点循环以免与命令补全冲突。

## 13. 实施顺序与验收

A：B视觉几何与编辑基本功，先做局部输入、连续多轮、开放代码、slash与正确焦点。B：状态闭环，追加/Stop作用域、配置、问题回答、失败/重试。C：Job对象与响应式阅读器，再接其他可用对象。所有产品事实仍经bone-app，不由renderer读Git、配置、数据库或provider。

必须验证的真实流程：

1. 输入两行中文/组合字符→发送→立刻写新内容→迟到回执→切会话→回原会话，草稿/光标不丢。
2. Running追加→收到Queued/Accepted→Stop；核实Queued取消与runtime停的真实范围，历史说明与App一致。
3. 菜单打开时Esc只关闭；详情Esc返回来源；Question退出恢复普通草稿；均不能误停工作。
4. 无模型已保存→选模型/登录→恢复原InputId，不能重复生成用户输入。
5. 历史上滚→新回复→改宽160/120/80→仍留锚点；显式回最新才跳尾。
6. 160对象→120对象→80对象→160对象→关闭→来源行→编辑；对象、位置、草稿全部保持。
7. 40×12菜单最后一项可达、主要动作可点；空右栏滚轮无动作，鼠标无点击穿透。

设计图只能验证布局和可见状态。实施后需要真实PTY、App集成、失败注入与现有仓库门禁，不能把SVG链接走通当成功能完成。
