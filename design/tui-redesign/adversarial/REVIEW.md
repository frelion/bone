# BONE · 对抗式设计评审

2026-09-10。前面的灰暗稿、浅色稿均已被用户明确拒绝，本轮不将它们作为待批准方案。推荐本轮 A 的完成稿，B/C 保留为真正的对照与反方，不拼成一个折中版本。仍为设计阶段，产品代码未改。

## 推荐稿：停靠式编辑工作区

![推荐稿](a/final-main.svg)

这次选择的审美方向是：清楚、明亮的靛灰工作面，较深的两侧目录区，正文接近白色，少量紫蓝用于状态；没有暖灰褐的浑浊叠加，也没有浅色网页表单。

整体关系比某个色值更重要：两轮内容连续展开，用户消息承担来源边界；代码摘录有文件头；输入停靠在中栏底端，与主画布组成完整工作区。它不再是一只浮在底部的长方形框。右栏保持默认空白，三栏职责没有改变。

我推荐 A 的原因：它在三份修订稿里，较好地同时保持了可辨识的编辑区域、连续终端工作面的整体性，以及比先前近黑主题更明确的明度层级。这个判断仍然有审美取舍：C 更轻，B 的开放代码更像连续文章，但我没有因此把它们的标记和装饰混进 A。

## 输入区：按内容决定分量

| 可见输入 | 编辑区总高 | 组成 |
|---|---:|---|
| 单行 | 4行 | 模型1行 + 间隔1行 + 输入1行 + 动作1行 |
| 两行 | 5行 | 模型1行 + 间隔1行 + 输入2行 + 动作1行 |
| 三行 | 6行 | 模型1行 + 间隔1行 + 输入3行 + 动作1行 |

去掉完整边框、半截角框、继续对话标题和多处散落的脚注。模型弱化，输入文字保持正文亮度，命令、换行、提交、停止在同一底行。输入增长时向上占用正文空间，底部动作位置稳定。生产实现需要上限与内部滚动，不能按设计图写死高度。

主稿两行草稿不是两行占位文字；三行稿验证新增内容的空间成本。80列稿按当前单区重新排版，未将整张宽图缩小冒充响应式。

## 对抗发生了什么

三个 agent 独立提出方向，各自产图后才互相看图。主 agent 同样提出反对，没有将三份初稿都称为“各有优势”。以下是决定性冲突。

| 方向 | 核心主张 | 被攻击的问题 | 处理结果 |
|---|---|---|---|
| A 停靠式编辑区 | 输入成为中栏底部工作面 | 一行文字占9行，顶底两块色带夹住正文，像控制台 | 删除顶部色带、重复标题与重复路径；输入先减到6行，最终按内容4/5/6行；补第二轮对话 |
| B 局部写作区 | 较窄阅读轴，代码直接融入回答 | 灰绿仍触发阴湿观感，孤立角标像坏掉的框，操作分散 | 去灰绿、去角标、合并元信息；保留两轮连续阅读与局部输入面 |
| C 原生提示行 | 输入与终端正文同轴，无独立面板 | 首稿只是旧图删框，单行浅底像选中行，省出的空间仍是空白 | 明确否决首稿，重排两轮内容，取消代码卡片和选中条，补多行与空输入 |

A 接受 B 的多轮阅读批评；B 接受 A 对灰绿与断角的批评；C 承认首稿失败，A 又接受 C 对重复路径的批评。最终没有用评分平均或“全员通过”来替代选稿。

仍然保留的反对意见：A 的停靠面依然比 C 重，模型顶行与台面边缘的关系仍需实机看；B 的阅读节奏值得保留研究；C 的透明输入在空态是否容易发现没有用户测试证据。文件路径来自示例内容，不能在实现时无条件生成。

## 行为核对与落地边界

运行中 Enter 是否可提交曾引起争议。已检查现有代码：`crates/bone-tui/src/state/update.rs:464`只阻止同一提交仍待回执时重复提交；`crates/bone-app/src/session.rs:509`接受输入后发布回执，再尝试交付队列；`crates/bone-app/src/persistence.rs:1492`把新输入保存为Queued。因此设计使用“Enter 提交”，不声称它必然立即改变当前执行，也不假造排队数。

宽屏依旧24/剩余/40；100–139两栏，40–99当前单区。所有全局动作仍走slash命令，A初稿左侧“+”已去掉。右栏保持默认空且无焦点；对象详情属于下一阶段设计接线，没有往空白里填装饰或假功能。

模型名、任务、文件和回复为设计样本，图中叙述的修改/测试不代表本轮实际执行结果。各候选的源文件保留探索痕迹，最终几何以 A 的 `final.py` 与 `final-*.svg` 为准。

本轮已完成：初稿与修订稿实际看图、交叉批评、推荐稿单/双/三行和80列检查、SVG有效性与几何断言。产品Rust代码未改，未进行产品回归测试。真实终端的字体回退、中文字宽、缩放锚点、编辑输入法和色彩降级仍需在实现阶段验收。

实施顺序：先把最终几何和主题映射到真实终端固定数据 → 实现按内容增长的编辑视窗和命中范围 → 接回真实App状态与Markdown块 → 验证迟到回执、会话草稿、滚动锚点与Esc优先级。设计被接受前不进入这一步。
