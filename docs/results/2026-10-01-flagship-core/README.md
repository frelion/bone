# 旗舰 core：工程验收前的内核修复

基线：`8119f3b`。本报告只说明故障复现与修复，不表示后续真实工程验收已经通过。

## 已复现问题及最小修复

1. **旧输入重复执行**：新输入包含旧要求并完成交付后，旧输入仍排队。增加内部 `input_resolve`，由 Agent 明确区分完成与替代；整个批次先校验，再以现有事件与队列同事务提交。未选独立请求保留，原预算不变。拒绝未知写、未完成原生工具批次、其他 Job 所有权及任何仍可恢复的委派输入。独立审查发现“失败但暂停的子工作仍可恢复”，已补充拒绝条件与回归。
2. **新源码尚未被工作模型看到就丢入摘要**：九个默认 8 KiB 源码页、64k 字符上下文的复现中，首个带结果的请求是摘要，每页只剩约 415 字符预览，后续工作请求没有原结果。现在从最近已提交原生工作响应推导未消费边界；先压缩更早历史，新结果必要时以整体预算内的可读视图进入工作请求。原调用参数、配对身份和 SQLite 原文保留，省略部分从原事件第 0 字符回查。无新增持久状态。
3. **交互 CLI 忽略总体超时**：配置一秒超时后，延迟模型仍交付、延迟 shell 仍完成。现在 `chat` 使用已有停止路径持久暂停；普通输入与 `/resume` 重启工作时限，不增加旧输入预算。取消写入保留未知结果，新进程可继续核查。
