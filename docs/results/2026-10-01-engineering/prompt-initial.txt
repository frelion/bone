请在这个 BONE 仓库实现一个实际维护需求：为公开 Rust 审计 API 和 bone history 增加按事件 ID 续读的有界分页，方便长会话的外部审计。保持现有 bone::history 与不传分页选项时的 CLI 行为和 JSON 数组格式。

CLI 新增 --limit N 和 --after EVENT_ID；任一参数出现即进入分页模式。初始默认 limit 为 200，有效范围 1～10000。游标表示最后已读取事件，下一页从它之后开始，按当前 session 持久化追加顺序读取，不能按事件 ID 或时间戳排序。分页 JSON 为 {"events":[...],"next_cursor":...,"has_more":...}：非空页的 next_cursor 是本页最后一个事件 ID，即使已是末页；空页为 null；has_more 表示读取时是否还有下一条记录。文本模式保持原来的事件行，并明确显示续读游标和是否还有记录。

未知 session、未知游标和其他 session 的游标必须报错。相同页请求稳定，后来追加的事件可以在续页中读到。返回原始 Event 内容，包括已压缩的源记录。分页的事件正文读取与内存开销应随页大小变化，不能先载入整个 session 再截取；为判断是否还有下一页，不应解析未被请求的记录正文。

请提供方便外部调用的公开分页 API、必要的离线回归测试和用户文档。自行调查现有实现、实现功能、运行适当验证并修复你发现的问题。保持恢复、压缩、权限、认证和其他执行行为；不要引入新依赖、Agent/Job类型或通用框架。不要修改现有测试的期望以绕过失败，不要提交或推送 Git。结束时如实说明修改和验证证据。
