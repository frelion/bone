# 真实仓库工程验收：历史分页

## 结论

BONE 使用现有 Codex 订阅和 `chatgpt:gpt-6-luna`，在 BONE 自身的隔离 Git
worktree 中完成了一个跨存储、公共 Rust API、CLI、测试与文档的需求。
第二次运行的首次交付通过独立 CLI 22 项与公共 API 17 项检查；没有向它提供
验收失败反馈，也没有由评审者补写实现。代码已原样集成。

这是一个真实仓库需求的成功样本。它尚不能证明大型陌生仓库、数小时任务、
多服务集成或无人监督工作的可靠性。第一次运行失败，记录保留。

## 任务与执行方式

候选基线为 `36d338d`。新增 `bone::history_page` 和 `bone history` 的
`--limit` / `--after`，保持旧完整 history 接口与 JSON 数组兼容。按 SQLite
追加顺序分页，游标限定 session，返回未裁剪的原始事件；不能先读完历史再截取。

- 初始要求的默认/最大页数为 200/10000。
- 检测到首次实际源码修改后，追加要求改为 100/1000，要求审计无模型配置、
  无模型调用、不改 revision、不获取执行 session 独占锁。
- 新指令的模型调用启动后，经公共 `Engine::stop` 暂停，此时没有外部动作在运行。
- 另一个 CLI 进程向同一 Session 发送普通“继续”输入，完成剩余实现。

三条原始输入保存在本目录。驱动只通过公共执行接口传入任务和暂停，没有替模型
分配 Job、修改候选源码或伪造工具结果。独立 verifier 位于候选 workspace 外。
编译缓存通过 `CARGO_TARGET_DIR` 复用，运行器是冻结的独立二进制。

## 保留的两次结果

| 记录 | 结果 | 模型调用启动数 | 完成摘要数 | 已观察 token | 时间 |
| --- | --- | ---: | ---: | ---: | ---: |
| 首轮诊断 | 无实现；人工 SIGTERM 终止 | 25 | 8 | 133,076 | 188.138 秒事件跨度 |
| 修复后重跑 | 首次交付独立验收通过 | 28 | 3 | 243,333 | 两进程运行合计 232.713 秒 |

两次各有一个未报告 usage 的中断调用，**总 token 与费用均未知**；表中 token
只是已观察下界。首轮没有到达预定的追加要求、暂停及恢复步骤。时间口径不同，
不能作为严格性能比较。本轮不是三次交替消融，也不估算成功率。

首轮 28 次源码读取中，25 次之后首先启动摘要，3 次之后首先启动工作模型。
过大的读取批次触发有界预览摘要，模型反复读取而没有修改源码。修复把默认
`read_file` 页从 32 KiB 调为 8 KiB，并说明 `next_offset`；显式最大页仍为
32 KiB。回归使用实际四个源码文件，验证默认页先完整到达工作模型再续读。
旧的大批次回归改用显式 32 KiB，仍验证超限情况下的原文保留和回查。
宽批次或显式大页仍可能触发预览；没有宣称消除了所有摘要信息损失。

重跑实际只使用一个持久 Job；28 次模型调用包含思考、3 次压缩以及一次取消。
30 次外部工具启动均有对应结果。BONE 先遇到格式检查失败、再遇到 clap 参数
编译错误，随后自行修正，最终运行测试、格式检查和 Clippy。外部验收没有参与
这些修正。任务交付后没有未知写；最新输入已交付，旧输入仍保留在 inbox，
**不是整个 Session 全部输入已终结或完全空闲的证据**。

## 独立验收与集成

- 冻结 CLI verifier：22/22，包括旧数组、默认值、边界、追加顺序、跨 session
  游标拒绝、追加续读、文本模式及页外损坏 payload 不解析。
- 补充公共 API verifier：17/17，包括原始 message/response/stream 内容、API/CLI
  一致性、非法页大小、持有真实执行文件锁时的审计、snapshot 不变。
- 只读源码审查：参数化 session 游标查询；SQL `LIMIT limit+1`，只解析前 limit
  条 payload；没有先物化完整事件历史。仅新增一个结果结构体和直接函数。
- 集成后：102 项 Rust 检查通过，格式、Clippy 警告拒绝、全部 feature 编译和
  build 通过；两组独立分页检查再次通过。1 项忽略项是由硬杀测试调用的子进程 helper。

分页限制事件行数，**不是总字节数**；单条大事件、session snapshot 和事件元信息
仍可能很大。`Store::open` 沿用既有初始化/迁移流程，连接不是 SQLite 只读模式。
Rust API 的 limit 显式传入，100 的默认值来自 CLI。本次不验证数据库迁移性能。

另两项执行器修复分别由离线回归覆盖：公共 `result` 在 resume 后不再把旧 failure
当作当前结果；shell 显式超时支持 1～3600 秒，无效值报错，取消和超时的未知写
保护不变。这些修复由开发者完成，未归为 BONE 自主产出的分页代码。
