真实订阅 · 鉴权修复

PASS gpt-6-luna，复用现有 Codex 登录，隔离 Python 仓库。

先确认失败，运行时插话要求只解释并提问；明确回答 401 后，修改源码并复验。8 次模型调用、6 次工具执行；原有 12 项测试保留且独立通过，只有 auth.py 改动。

这是本轮功能实现期间的真实任务记录；画面属于中间构建，最终界面见上一级报告。模型交付后旧验收脚本因页脚文案断言停止；修正断言后重新打开同一持久会话，没有重放模型请求。费用未知。

真实对话

输入

修复过期 token 被接受的问题。先运行 python3 -B -m unittest -v 确认失败，再定位源码。保留 authorize(token, now) API，不修改测试，不提交 Git。

输入

只解释原因，先不要改文件。请用 ask_user 问我过期时希望返回哪个状态码，等我回答再改。

问题

原因已定位：`auth.py` 的过期判断方向写反了，当前 `expiry > now` 时拒绝，反而让已经过期或刚好到期的 token 通过；而未来到期的 token 被拒绝。测试运行确认 12 项中 6 项失败。请问过期（含到期时刻）的 token 希望返回哪个状态码？

明确回复

返回 401；现在允许修改 auth.py，并运行原有12项测试验证。不要改测试、不要提交Git。
