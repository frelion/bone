# 生成续做与分步文件写入验收

范围：`codex/core-simplify` 的实现阶段验收。下面的指纹保留版本号更新前的实验快照；后续 0.10.1 的原生发布验证见[发布说明](../../releases/0.10.1.md)及安装包中的 `release-builds.json`。基线为已发布 0.10.0 的 `b674fc9edcd51cdcaf3c360aae38a985ccb2f78b`；本报告不把新的源码行为归入原发布包。

## 实现

- 保留单个 Session 执行器、普通 Job、六种状态和 Rig 原生类型。工作、摘要与恢复都消耗原输入的共享调用额度。
- `Length` 整轮只审计，同输入最多续做一次。完整工作回复才重置工作机会；摘要独立计算。停止、恢复与重启不退还已经启动的机会。
- 过滤、明确上下文限制、其他结束原因和调用错误分别暂停。完整 JSON 在受限回复中仍不准执行；空的成功回复不算工作进展。
- `write_file` 必填 `replace | append`，追加检查上一版 SHA 并复用原子安装，返回整个文件的新 SHA/大小。权限、冲突和 16 MiB 总大小边界保留，没有新增暂存生命周期。
- 摘要没有隐藏的 2048 截顶。受限时只重试不超过原失败源一半大小的完整前缀；提交前验证完整工作请求实际缩小。失败原文及旧摘要保留。
- 配置、服务端报告和安全原生观察分开记录。停止也保存已观察到的部分，用量未报告时保持未知。调用结束的状态与原生结果在同一事务提交。
- TUI 自动续做显示“本轮生成未完成，正在继续”；最终暂停给出原因和保留进度。用户不管理 Job。

大 fresh 工具结果的单独回归证明：续做事实在请求预算中预留空间，有限预览和原始输入可以同时送出；失败生成不被摘要误算为已消费工具结果。

[verification.json](verification.json) 保存最终二进制、关键源码和检查指纹。最终 PTY 二进制与固定消融二进制相同。

## 固定协议对照

[ablation.json](ablation.json) 保存相同任务、Rig 请求配置、总调用额度、源码补丁和二进制 SHA、三组交替结果与原始证据路径。

任务先接收一个完整 JSON、但原生 `Length` 的整文件写入提案；之后由固定 fixture 提供两个完整片段，执行 replace、append、read 验证并交付。目标文件 36,047 字节，内容及 SHA 在执行器外核验。

| 版本 | 完成 | 每次模型调用 | 工具执行 | 未完成提案副作用 |
| --- | --- | --- | --- | --- |
| 0.10.0 基线 | 0/3 | 1 | 0 | 0 |
| 当前候选 | 3/3 | 5 | 3 | 0 |

这是持续推进能力的收益，需要额外调用。fixture 人工报告每次总 token 分别为 8,292 / 20,212，不代表真实推理成本；费用均为 `null`。这些受控实验不能证明任意模型都会选择更小动作，也不能证明生产 New API 的表现。

## 真实订阅两轮任务

[live.json](live.json) 记录复用现有 Codex 登录、`gpt-6-luna` 经原生 Rig 完成 Python 金额解析修复，并在 CLI 重启后继续支持括号负数。独立校验覆盖整数精度、旧规则和新增边界；测试文件 hash 与初始源一致。

两轮均交付，分别 8 / 6 次模型调用，共 12 次工具执行；实际调用 `write_file replace → append → append`。服务端共报告 46,676 token，费用未知。两轮耗时约 24 / 30 秒，原始 Session 在本机验收目录保留。

本次真实订阅调用没有触发 `Length` 或摘要；受限恢复和摘要故障由上述原生协议测试证明。缺少用户另一台机器的 New API 响应及凭据，远端报错的具体触发原因仍未知。这份本地实验记录不包含后续 Windows/Linux 原生发布验证。

真实任务在最后一轮事务提交与停止诊断细化前完成；最终代码另经完整回归、PTY 和固定协议对照复验。
