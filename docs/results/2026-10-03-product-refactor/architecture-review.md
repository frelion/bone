# 全产品重构：架构裁决

目标：简单、自然，如非必要勿增实体。一个 Session 只有一个 Agent，思考与工具仍归属内部 Job。

## 先修产品事实的归属

### 1. 删除中文文案驱动的消息分类

旧 `Message.role: String` 同时承载展示文字和行为。View 用 `starts_with("工具")`、`contains("失败")`、`contains("输出中")` 决定消息类别、颜色、折叠和标题；控制器用 `text.starts_with("执行中 · 实时日志")` 决定复制持久结果还是实时观察。这使文案调整改变行为，最终文件引用同样的文字也可能被当作实时日志。

现在控制器从已存在的事件事实投影 `MessageKind`；工具只携带名称与 `ToolState`。正文保留原始观察，名称只用于显示。工具状态判定一次，同时生成可读文案与展示事实。用户接收/纳入事实、问题、交付、进度、流预览、失败、暂停分别表达。

`selected_tool_observation` 是普通函数：必须同时满足工具仍 Running，以及既有 `tool_observations` 中确实收到对应调用的进度。工具刚启动不冒充已收日志；完成后的正文引用旧提示不变成实时快照。

必要性判断：

1. 明确需求：改变文案不会改变类别与行为；未知写、失败和未交付输出不能互相冒充。
2. 普通 String 不够：文字不能稳定表达这些已有互斥事实。一个具体枚举足够，没有 trait、注册表或展示协议。
3. 消融：恢复中文解析后，任意工具名、翻译或正文引用再次影响事实判断；8 项验收中的工具结果与实时快照反例会失去保护。
4. 成本：替换一个现有消息字段，新增工具阶段枚举；同步迁移构造点、样式投影和测试字面值，没有改变 core 事件格式或持久化。

### 2. 输入目标从现有绑定派生

旧 View 通过 `reply_label.starts_with("新要求")` 或 `starts_with("回复")` 控制目标条和操作提示。现在 `InputTarget::{Message, Reply, Reconcile}` 由控制器已有 `reply_target` / `reconcile_call` 派生，展示标签可以简化。它不保存新的目标 ID，也不拥有新的路由或执行状态。

这是展示与输入绑定之间的最小事实边界。删除它必须重新解析中文，或将控制器的整个草稿/核查状态泄露给 View。Draft、读锚点、光标和选区的所有权保持原有范围。

### 3. 空闲修改连接不再制造一次“用户停止”

旧 `apply_connection` 无条件调用 `Engine::stop`；空闲切模型会递增 revision，记录 stopped，并要求 Ctrl+R。现在直接复用 `Engine::is_quiescent`，确有活动工作才暂停。已暂停的会话不重复停止，空闲保持空闲；真正被暂停的工作仍需要明确恢复。

保留 Engine 的静止条件、配置修订检查、失败时模型回滚、凭据独立保存和未知写核查。配置冲突不会覆写另一个编辑器的内容。

本轮没有为了这一条件新增执行状态机。App 的 `Settings` 当前副本暂留在既有配置事务中；删掉它需要迁移所有启动接口和 core 只读 getter，目前没有独立产品失败证明这比上述行为修复更优先。

## 保留与删除的裁决

| 结构 | 裁决 | 原因 |
| --- | --- | --- |
| Engine / Session / Job | 保留 | 执行归属、版本屏障、取消、持久化和未知写的一致性边界 |
| 原生 Rig 接入 | 保留 | 无须再建立模型协议和 provider 平台 |
| 中文 role 分类、中文实时日志前缀判定 | 删除 | 文案与正文不是行为契约 |
| 中文输入目标前缀判定 | 删除 | 已有真实绑定可直接投影 |
| LayerReturn | 保留 | Esc 返回上一层与原阅读位置有明确生命周期 |
| 读锚点与输入选区 | 保留 | 长历史和多轮交互的验收需要这些状态 |
| 通用 action bus / UI runtime / 任务管理平台 | 不引入 | 当前普通函数与具体状态足够 |
| 会话专用 catalog / 状态平台 | 不引入 | 左栏仅呈现目录投影出的短状态，不据中文产生行为或排序 |

## 验证与边界

新增 `tests/unit/tui_presentation.rs` 8 项测试，覆盖空闲切换、活动请求切换、已暂停切换、配置冲突、真实工具返回分类、矛盾文案的实际投影/终端渲染、输入目标事实和实时观察归属。新增测试已通过；现有测试只迁移 Message 字段，由界面所有者更新设计改动对应的布局断言。最终全量 gates 和 PTY 证据由统筹验收汇总。

颜色投影直接检查实际消息渲染函数；终端启用 NO_COLOR 时仍验证正文呈现，避免为测试修改进程共享环境变量。测试使用临时目录和机械事件，无个人凭据或真实模型调用。

当前一个活动 Engine 的会话切换仍暂停旧工作。旧会话后台继续运行属于多 Engine 生命周期设计，需单独确定退出、恢复与 workspace 写冲突政策；不混入本轮视觉打磨。

## 实际表单推动的名称减法

产品审查在真实连接表单中输入“团队开发 API”，底层 ASCII 名称校验拒绝了正常命名。核查没有发现 provider 协议需要 ASCII：连接名只作为配置键及 `profiles/<name>` 的路径组件，TOML 由现有 serde 正确引用。

直接放开现有名称的 Unicode 字母数字与普通空格，保留 `_` / `-`；首尾空格、点、路径分隔符、控制字符、不可见字符及 TOML 标点仍被拒绝，沿用原 80 UTF-8 字节上限。没有新增 displayName、内部 ID 或路径映射；已有 ASCII 名称与凭据路径不变。

新增 4 项配置验收覆盖多语言与字节边界、真实 TOML 保存、中文 API/订阅缓存路径及独立凭据隔离、Unicode 目录的现有 API 凭据 symlink 保护。`cargo test --lib config::tests` 共 9 项通过。订阅测试仅检查本地路径与缓存存在性，没有声称完成真实订阅认证。

## 最终生命周期审查

- `SavedDraft` 是现有草稿的持久记录，解决真实终端发现的切会话/重启丢失未选中回复稿；不是第二套编辑器状态机。空回复槽不保存，避免已完成问题耗尽目标上限。删除它会重新丢失多目标未发送文本；单稿、聚合与数量限制仍在写入前验证，原子保存保留。
- 通知文字、强度与计时器归 View 的 `notify/fail` 同时更新。删除 App 的旧计时器副本和文字比较，避免新异步错误被旧成功回执的期限清掉；错误没有自动期限，用户后续操作可以替换或清除。
- 历史键盘选中边界与鼠标物理顶部用两个普通查询函数表达，鼠标按实际正文 Rect 命中。`at_history_top` 不以 selected=0 冒充正文顶部；每次旧页读取推进持久游标，不启动模型或工具。
- 导出完成只保存一个最近结果路径并提示。用户主动打开完整路径及复制入口，后台结果不更改当前表单、草稿或阅读层。删除该路径会使窄终端中被截断的结果不可达；没有新增导出任务平台。
- Draft 恢复直接构造已有 TextArea，位置恢复与字节定位共用普通函数；删除为恢复一份草稿而构造完整 View 的临时依赖。
- 这些机制只服务已有丢文、计时器、阅读与结果可达性失败。一个 Agent 与内部 Job 的执行边界、Rig 协议和 core 的写保护没有改变。

### 完成交付后的恢复提示

独立复验发现已完成 Idle 的 Session 重启仍保留退出时 paused=true。UI 若只投影这个开关，会让用户恢复已完成工作。`has_unfinished_work` 普通函数从 pending_inputs 与非 Closed Job 的 state/active_input/inbox/wait_for/current_call 推导是否仍有工作；与已有恢复边界一致。主运行行、左栏和切换回执共同使用它，未知写仍先显示核查。一个真实本地 Job 的交付、切走、切回回归证明完成项不提示恢复且没有追加模型调用；未修改内核暂停策略。

### 宽字符尾格的终端更新

实际终端差分与独立xterm复现了普通宽字被逆色窄光标覆盖后的尾格残影。原生产渲染缓冲没有第二个光标，既有光标函数现在仅将窄光标后一格标为AlwaysUpdate，以当前真实样式刷新。普通宽光标不强写被字形占用的尾格；每次最多多一个终端格更新。没有新缓存或渲染协议。真正4/4的PTY检查断言非活动父输入行没有逆色块，TestBackend另检查父稿光标被隐藏。
