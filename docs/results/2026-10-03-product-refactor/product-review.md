# 全产品视觉打磨：提案与反例

本轮按生产 TUI 的实际终端格评判，不用网页原型替代终端。基线来自 0.8.1 的 80×24 / 120×40 PTY；提案与反方直接交换截图，根同时审查交互事实和架构边界。

## 已收敛的画面

- 左栏每个会话一行。当前用 `•`，浏览候选用 `›` 和整行反选；两个身份独立。右端只显示最高注意状态：核查、回复、暂停、运行、等待。标题按剩余显示格中间省略，保留结尾差异。删除时间、固定元数据第二行和重复教学。80×24 的列表可显示 21 项，120×40 可显示 37 项。
- 主区顶部两行使用原来的总高度：第一行固定项目，第二行连接与模型。长配置名称不再挤掉项目，尾部模型差异保留；删除装饰分隔线。
- 空态教学只在输入 placeholder。输入焦点由真实光标和边界表达；阅读时留下“草稿”，操作键只出现在当前层的一处。常态不写“输入中”。
- 表单高度由当前编辑、公开值回顾、错误和操作提示决定。最后一个字段可核对之前的非密钥值；密钥始终遮罩。四字段 API 表单保存页占 10 行，不再把单字段编辑画成接近整屏的空框。父草稿保留，父回执隐藏，当前真实运行事实仍可见。
- 命令候选的提示与实际动作一致：Enter 执行、Tab 补全；文件引用只插入。错误具有文字与强度，最多占两行；完整错误数据保留，失败不作为普通成功回执静默过期。

## 对抗过程

1. **反对单行丢状态。** 反方给出登录回归待答、账单迁移未知写、缓存清理暂停的混合反例。最终保留每项的最高注意状态，不能只在栏底或当前会话显示，也不以时间取代状态。没有引入状态分组、排序设置或新面板。
2. **反对只用同前缀编号证明可读。** 候选截图改用现实任务名称和混合状态，再分别检查 80、120 列。相同开头的 Linux/macOS 名称用于检查结尾差异；真实 Job 的文件读取、段落和列表用于检查主正文层级。会话注意状态板由机械数据构造，明确不宣称这些会话都经过真实故障恢复。
3. **纠正截图字形假反例。** 首次浏览器回放把圆点画成半圆、箭头画成逗号。反方查出共享回放器在行内写死 `monospace`，覆盖页面终端字体；修成继承声明字体后字形正常。取消因此提出的 ASCII 替代，保留全产品一致的 `›`。该问题属于证据绘制器，不冒称原生终端字形修复。
4. **拒绝错误的保存页证据。** 第一批 API 截图仍在 3/4，机械脚本的后续字段错入 endpoint，不能支持“密钥遮罩和保存回顾通过”。显式等待字段后发现中文连接名被旧 ASCII 规则拒绝。修正机械输入并重新录到真正 4/4；架构师随后允许现有连接名使用安全的 Unicode 字母数字与空格，保持单个安全路径组件，不增加第二个显示名称。
5. **反对宽屏巨型空表单。** 根指出 120×40 单字段表单占约 28 行。改为按实际内容计算高度，操作提示紧贴内容。反方重新看过真正 4/4 的 80/120 帧后接受这版。
6. **反对默认工具短 ID。** 成功工具一行末尾仍出现八位内部标识，80 列挤掉有用摘要。要求在控制器摘要中删除，事件身份与审计关联继续保留。

7. **反对完成后仍要求恢复。** 独立复验发现12轮完成后重启，所有 Job 已 Idle，但退出保护留下 Session.paused。统一按既有未完成输入与 Job 字段判断恢复提示：完成项不显示“暂停 / Ctrl+R”，未知写仍优先核查，未完成工作仍提示恢复。保留内核安全策略，不增加执行状态。

8. **反对表单中的第二个光标块。** 最终复看发现父草稿残留一格反色。原始 ANSI 与独立 xterm.js 都证实：普通中文宽字被逆色窄光标覆盖时，尾格连带清空并继承逆色；单看渲染缓冲无法发现。既有光标函数对窄光标后的一个真实格显式刷新，最多增加一个终端格写入，不增加状态。真正4/4新增父草稿无逆色残影检查，保留修复前关键帧。

## 通过的范围

提案与反方均接受单行左栏、混合注意状态、正文层级和紧凑保存页。候选视觉录制的当前工作经历两个真实本地协议 Job 请求和一次真实文件读取；其他会话是机械状态板。它证明画面和输入协议，不证明模型质量。

语义回归新增长模型不丢项目与唯一空态提示、保存页公开值回顾及密钥不泄露、操作提示唯一、表单内容高度和父点击区域遮罩等边界。最终安装版和完整验收范围由本目录的交付报告另行记录，候选截图不替代最终验收。
