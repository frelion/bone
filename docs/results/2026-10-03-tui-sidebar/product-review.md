# 左栏与 Shift 焦点：产品审查

日期：2026-10-03。目标是让会话切换清楚、连续，减少需要解释的交互。本轮以生产终端记录复审；需求文档和 Rust 测试不能替代画面证据。

## 三轮收敛

### 第一轮：修正信息组织

旧版实际 80×24 记录中，固定 22 格的左栏把中文标题压到约 8–9 字；“· 当前”拼在标题尾部，容易一同截断。状态藏在栏底，无法快速判断各会话。`SessionState.revision` 被标为“轮”，配置和停止事件也计入其中。

采纳的最小改动：

- 每项固定两行：标题、弱元信息。当前标记独立于标题。
- 80 列使用 26 格左栏，宽屏约 30 格、上限 32；低于 80 列显式展开。
- 删除虚假轮数和闲置时的“已保存”，显示实际需注意的状态和相对活动时间。
- 当前会话与浏览候选分开表达，后台刷新按 ID 保留候选。
- Shift+方向键切焦点；输入区 Ctrl+Shift+方向键选区。模态表单保留自身编辑行为。

### 第二轮：补齐容易失真的边界

| 发现的问题 | 采纳的修正 |
| --- | --- |
| 首行为空白时，已有要求仍可能显示“新对话” | 机械查找第一条有效用户文本中的非空行，保留原事件正文 |
| 长标题前缀相同，右侧省略使各项无法区分 | 中间省略，保留标题末尾；不生成摘要 |
| 暂停后残留 Ready/Running，可能仍显示进行中 | 暂停事实压过可执行 Job 的静态状态 |
| Job 等待依赖可能被误称待回复 | 只有未回答、所属 Job 未关闭的用户问题才算待回复 |
| 待核查被暂停或问题状态遮盖 | 待核查优先；必要时并列显示“已暂停” |
| 鼠标打开存在行定位和层级风险 | 标题及元信息映射同一会话；模态、原文层阻止穿透；空白不切换 |
| 会话刷新可能重新选中当前项 | 保存浏览候选的运行身份，更新列表时不抢焦点 |

重要事实的优先级为：待核查、待回复、暂停、进行中；依赖等待单独显示为“等待中”。未知活动时间省略，闲置不宣称全部完成。

### 第三轮：用实际 VT 挑错

审查中间构建 `2329ebd7` 的实际终端记录后，确认两行列表、当前与候选、长标题末尾和窄屏导航成立；同时发现一项需要修正的回执：

- 打开闲置会话时，正文显示“等待输入”、当前项没有暂停标记，但固定回执仍提示“未完成工作保持暂停，Ctrl+R 继续”。现已按新会话真实 `paused` 分支：未暂停只显示“会话已打开”，暂停时才说明恢复。
- 阅读态拒绝粘贴的提示仍指向旧操作。现已改为“返回输入区后再粘贴 · Shift↓”，与新焦点契约一致。

这两项修正已核对生产源码。随后复审安装版 `08cff694` 的最终 80×24 NO_COLOR 记录：帧7/8只显示“会话已打开”，不再提示恢复。阅读态粘贴提示的改动此处只作源码核对；完整重验的构建身份和结果以 [验收记录](acceptance-results.md) 为准。中间帧保留用于展示问题来源，不冒充修正后的画面。

## 没有增加的东西

- 不引入卡片、图标墙、时间分组、项目树或内部 Job 列表。
- 不添加 `n` 新建快捷键。本轮保留 `/new` 和统一操作菜单，避免再增加一套同义入口。
- 不新增公开 slash 命令；不保留 Ctrl+方向键与 Shift 并行的两套焦点入口。
- 删除左栏常驻的重复操作提示。正常侧栏只在必要时显示位置，窄屏展开时给选择和返回说明。
- 不使用模型生成会话标题，不显示 UUID，不增加标题摘要管线、日期依赖、UI 调度框架或会话目录的持久字段。输入草稿保存补充光标和选区两个字段，用于修正切换与重开后丢失位置的问题。

## 实际画面支持的结论

独立产品复审直接读取了 [最终安装版 80×24 NO_COLOR 的生产 VT 数据](pty/80x24/sidebar-flow/sidebar-flow.json) 的 12 帧及 `cell_styles`；[中间构建必要对照帧](intermediate/build-2329ebd7/pm-review.html) 保留用于展示修正前的回执：

- 候选01的反色只覆盖自身两行；当前00保留粗体和独立“当前”。NO_COLOR 下二者仍能区分。
- 相同中文前缀保留 `任务01` 至 `任务32` 的不同末尾，33项列表能滚到最后一项。
- 后台交付后，浏览候选仍是候选01，当前会话没有夺回选择。
- 点击标题与元信息分别打开正确会话；实际 Session ID 由 harness 独立核对。
- 42列时打开同一会话栏，导航文字完整；缩放后 Esc 返回原稿，无额外提交。
- 编辑与只读状态的光标、边界和 Shift 提示相符。

中间构建六组 PTY 均通过：80×24 NO_COLOR、120×40 NO_COLOR、80×24 颜色各运行 `sidebar-flow` 和 `workspace-flow`。产品复审另核对了最终版的上述 80×24 NO_COLOR 帧；最终其余运行的状态由验收记录维护，避免把中间结果算成最终通过。

## 证据范围

列表中的32个历史会话由 fixture 写入有效用户事件和 Idle Job，是测试数据；不能视为 AI 完成了32个任务。后台刷新使用真实 Engine、Job 和延迟交付的本地 HTTP fixture。API 和订阅协议凭据也由 fixture 生成，本轮没有读取个人登录缓存或再次调用远端模型。

空白首行、状态组合、空态、加载错误、模态阻止点击等边界由相应 Rust 单元测试覆盖；本轮 PTY 未注入全部这些条件，不能称为逐项实际终端验证。产品复审也未验证所有终端主题、Linux 剪贴板或远端认证失败。

HTML 是实际 VT cells 的回放，浏览器配色近似 ANSI。中间省略仍会隐藏标题正文，打开会话可读取完整原话。本轮没有为这一限制增加预览层或额外命令。
