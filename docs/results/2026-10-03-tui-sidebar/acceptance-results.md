## 场景及独立证据

`sidebar-flow` 在独立数据目录机械写入 32 个会话，每个会话有有效形状的用户输入事件及所属 Idle Job。这些内容是测试数据，不能视为模型完成的 32 个任务。另一次用户输入经过真实 Engine、Job 和本地 HTTP Responses fixture，延迟四秒交付，从而触发实际后台列表刷新。

它检查：

- Shift 四方向移动焦点，Ctrl+Shift 选择中文文字，系统剪贴板 fixture 收到精确选区。
- 焦点返回保留原选区；草稿、光标及未提交内容保留；焦点操作不产生模型请求。
- inline slash 候选关闭后进入左栏，命令未执行、草稿未提交。
- 同前缀中文长标题中间省略、末尾 `任务01/02` 可辨；NO_COLOR 下候选行的反色属性与当前会话标识分别存在。
- 后台交付与异步刷新不改变浏览候选；Enter 打开的实际 Session ID 通过本地 `/status` 核对。
- 超过一屏的列表可滚至第 33 行；不将版本号显示为轮数。
- 标题行与其下一元信息行单击分别打开正确 Session ID，上一会话确实暂停。
- 42 列时显式展开会话栏，经过宽窄 resize 后 Esc 返回原输入位置；没有额外模型请求。

`workspace-flow` 保留原生 API 与 ChatGPT 协议的本地 fixture、连接和模型持久化、重启、回复目标、续接草稿、极窄表单禁止不可见提交等验收，并将焦点键更新到 Shift 契约。所有凭据由 fixture 自己生成；没有读取个人登录缓存或调用远端模型。

最终完整 VT cells、SGR、硬件光标、事件与 HTTP 请求计数在 `pty/` 各 JSON；HTML 是这些实际终端数据的回放，浏览器配色近似 ANSI。指纹和结果汇总在 `fingerprints.json`。

- 当前项使用独立元信息，长标题不能吞掉“当前”；聚焦候选采用两行一致反色，视觉上可区分浏览与已经打开。

- 同前缀长标题保留末尾，32 条记录仍可按实际任务编号辨识；没有模型生成标题或 UUID 噪声。

这些证据支持本轮交互契约，不等同于所有终端主题、所有 Linux 剪贴板或真实认证路径的验收。空态、加载失败、模态点击穿透及状态组合由 Rust 单元测试覆盖，本次 PTY 未伪装为已注入这些故障。
