# 0.10 内核收缩与验收

基线：`265aae76fc5a1fea633fc1f3d1d43798c5eb8e75`（0.9.4）。实现分支：`codex/core-simplify`。

## 删除的机制

- 删除 `UnknownWrite`、会话级未知写门禁、pending 标记和人工 `/reconcile`。
- 工作区与认证源各只用一把物理锁；删除双锁兼容接线。
- 删除旧 SQLite 补列、日志回填、旧快照修补和旧 TUI 草稿格式 fallback。
- 删除隐藏的旧 slash 别名和 F6 焦点绑定；公开命令只有 `/new /model /connect /help /quit`。

没有新增执行框架。模型、工具、摘要仍归属同一种 Job，由一个 Session 执行器提交状态。中断成为普通原生工具结果，由 Agent 根据实际状态决定后续动作。

本次生产源码净减少 408 行。新增测试覆盖实际进程、持久化失败和多轮输入的生命周期；删除仅证明旧兼容行为的测试。

## 保留并修正的边界

- 停止保留工具句柄和物理锁，收集真实输出与终态；已经启动的调用不自动重放。
- 新指令阻止旧提案启动动作；明确替代旧要求可以结算其委派，独立任务不被误取消。
- 当前回复结束后不自动重新执行旧用户请求。原输入与预算仍保留，后续可以续做。
- 会话切换、换模型和编辑草稿不隐含停止；每个已打开会话独立推进并保留运行配置和时限。
- CLI 在对应输入终结后退出；其余已启动执行先取消并收集，不等待它们自然完成新交付。
- SQLite 提交失败后执行器拒绝继续修改，重开从持久启动意图恢复。

会话使用 `sessions.sqlite`。旧文件保留，旧会话不迁移；当前连接配置继续使用。自有快照的必需字段必须存在，未知字段被拒绝。恢复只处理当前格式的已启动工作。

## 跨平台门禁中的测试修正

[首轮原生预检](https://github.com/frelion/bone/actions/runs/37742297325)的两种 Windows 架构在停止回归的就绪等待中超时：五秒内未观察到实时 stdout，尚未调用 `stop`；该日志没有确认具体超时原因。其余 Windows 输出收集和后代进程测试通过，两种 Linux 架构的完整流水线通过。

该回归改为 stdout 刷新后的真实文件标记作为屏障，有界等待冷启动；提前结束则收集真实工具结果并直接报告错误。所有调用归属、唯一原生结果、部分输出与物理锁断言保留。生产源码没有因此修改；修正后的单项本机通过，跨平台结果以新提交的流水线为准。
