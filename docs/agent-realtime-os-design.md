# bone-agent：双模型，一个内核

状态：2026-09-08，核心重写与设计审阅问题已收口。当前范围是 bone-agent；bone-app 迁移独立进行，没有旧 Agent API 兼容层。本文件说明当前实现，取代此前“可选协调模型”草案。

## 1. 最终分工

**Kernel 模型管工作，主力模型做工作，代码 Kernel 维护真实状态。**

保留五个抽象：Event 是输入；Kernel 是唯一状态写入者；Effect 是执行指令；Runtime 是异步执行器；Job 是持续的语义工作。模型、调用、队列和等待条件都是这条执行路径中的协议细节，不是额外的 agent 框架。

Kernel 模型读原话、工作目录和公共摘要，短时提出分派与跨 Job 控制。它不调用业务工具，也不回答专业问题。主力拿到原文和确定的工作归属，独立研究、使用工具并交付；普通工具结果和答案不需要再找 Kernel 模型审批。

新输入先短分派，已有主力继续执行。没有为每条补充或取消消息预建临时 Job，也没有两个模型竞争消费同一条输入。

## 2. 工作、输入和调用不混为一谈

Job 保存目标、状态、成果、输入关联、父工作、引用和当前有效调用。输入与 Job 多对多；每条 Input 另外记录本次请求的 required jobs 与交付结果。

JobId 是持续工作；CallId 是实际调用；InputId 是宿主提供的原始输入身份；Seq 标识权威记录、路由与成果引用。没有额外的 EffectId。`CallContext::id()` 仅在同一 Runtime 内唯一，外部幂等键需要组合宿主提供的 Runtime 或 Session 标识。一次调用完成不等于 Job 完成，一条回复也不等于全部交付完成。

拥有关系可以级联取消，引用只提供证据。等成果可用不要求生产者终止。普通追加材料不统一作废在途求解；目标、控制及关键外部确证改变时，仅撤销有关提案资格。

Report、Published、Outcome 和 Inquiry Answer 的显式 evidence 向相应接收者开放定向读取，未列出的私有记录仍隔离。Completed Job 的 seed 始终使用最终 Outcome summary，并授权读取该 Outcome 与最终 evidence；checkpoint evidence 可以补充背景，较早摘要不覆盖最终结论。

工作发现需要协调时通过 Coordinate 发出请求。历史输入关联不等于新的用户授权：source 请求不能修改已有目标、恢复暂停或重写会话约束；只能控制自己拥有的工作树及派出子工作。

## 3. 调度与输入解释

默认容量：1 个协调模型槽、1 个交互主力保留槽、2 个后台主力槽、8 个工具槽。User 根工作进入交互 FIFO 并优先调度，也可使用空闲总容量；其他 Job 进入后台 FIFO，同时受后台槽数限制。

每 Job 一个有提交资格的主力。旧调用请求取消后仍占实际容量，直到本地结束。工具槽释放后重新检查待提交候选；等待工具、用户、时间和成果不常驻模型。当前队列不承诺后台按根工作公平轮转。

未完成普通输入上限默认 32，另有一个关联澄清信封。Busy 明确表示未接收，宿主保留原消息。Stop、retry 和关联澄清有独立的控制或接收入口。Delegate 达到活跃 Job 容量时整批拒绝，把 Audit 写入父 Context 并重新调度，不把父工作判为 Failed。

一个固定批次只有一次有效解释。失败不自行重试；显式重试使用原 Input ID。新的普通输入会与所有未关闭输入路由中的原话按接收顺序形成新批次，包括 Failed、等待澄清、询问、调查和在途 Coordinate 的路由。旧路由关闭并撤销 Call 与调查树资格，原 Input 改关联到新批次，继续保留交付义务，不提前生成 InputFinished。旧结果与 Retry 不能恢复旧解释权；已解释完成而只在等业务 Job 的输入不重新路由。

复杂语义可委派普通主力调查，或等待用户澄清。调查及其子工作只能使用只读工具；内部 Outcome 可以穿过用户交付门禁，返回所属解释路由。调查完成、失败、取消和被取代都有明确归属处理。

协调者的默认目录首页与显式 Read 目录页同时受 16 条和完整 context_bytes 预算限制。最新查询页替换默认首页；旧页仍保留为权威记录，模型投影只显示本 routing 最新查询页，避免翻页累积上下文。

## 4. 行动边界

未解释的自然语言暂扣新业务写入和可能被取代的旧最终答案，已获准的计算和调查继续。新的普通输入仍按接收容量进入并取代旧解释批次；关联澄清使用预留信封。持续歧义可以持续阻止用户交付，输入和路由状态公开其原因。

候选在真正提交时检查当前等待关系与执行资格，不能用最初通过的检查代替现在的状态。所有控制变更先验证整组，包括父子取消冲突，再原子应用。

Stop 撤销它之前已接收的输入分派及工作资格，迟到的模型、工具进度和定时器不能复活旧工作。尚未被 Runtime 接受的消息仍由调用方管理。

Pause/Resume 的实际状态变更写入 JobControlChanged，便于增量观察。最后一个 Agent handle 被丢弃时，Runtime 自动执行 Stop 并进入 shutdown 清理；需要取得清理报告时由宿主显式调用 shutdown。

外部动作获准开始、实际提交与远端完成是三个时间点。已授权后才收到停止，只能尽力取消并核对真实结果。一个未决写入许可覆盖整个会话；Unknown 只能由宿主确证，不随 Job 取消清除，不自动重发。确证后相关工作重新思考基于 Unknown 的提案。

正常 Finish 除必要消息、询问、本 Job 工具及子工作终态外，还检查整个拥有子树的 ExternalWrite。Running、CancelRequested 和 Unknown 都阻止成功交付，子 Job 已取消也不能绕过；失败或取消仍可立即封存 Outcome。

会话 constraints 是模型可读的语义要求，不是权限 DSL。权限、数据出境、隔离和条件写仍由宿主与具体工具负责。此内核没有继承任何论文的形式化安全证明。

## 5. 明确不做的事情

本轮不迁移产品 app、存储、凭据或模型服务层。保留已有 read/glob/grep 与外部写端口边界，不新增业务工具。

不实现跨重启续跑、共享浏览器或桌面租约、多租户治理、通用预算系统、分布式一致性、硬实时控制及任意资源的事务隔离。内存事件记录不代表持久恢复。

当前 API、源码入口与运行示例见 [crate guide](../crates/bone-agent/README.md)；自动化场景和边界见[验证文档](agent-realtime-os-validation.md)。旧模型职责文档与历史认证只供追溯，不是当前实现规范。
