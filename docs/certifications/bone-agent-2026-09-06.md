为了稳定覆盖“新要求先到、旧分析后到”，测试可以暂缓交付第一次分析的真实结果，直到新要求得到确认。
所有模型请求和产物都来自真实接口，没有伪造或改写模型结果。事件记录另行标明进度回复时提供方是否已返回；本轮为 `false`，证明当时两个模型请求确实重叠。
停止场景不使用交付延迟；取消回调证明本地任务已响应取消，不代表远端计算已停止。

## 试跑发现与处理

- 旧配置中的 `gpt-5.4` 被服务端拒绝。官方文档也确认 `gpt-5.4` 和 `gpt-5.3-codex` 已退出 ChatGPT 登录通道，最终改用上述模型。[OpenAI 模型说明](https://learn.chatgpt.com/docs/models)
- HTTP 400 原来被归为 `Transport`，容易误诊为网络问题。现在有 HTTP 状态的服务端拒绝归为 `Provider`；连接中断仍归为 `Transport`，新增两项回归测试。
- 一次试跑出现了不符合完整决策结构的输出，适配器拒绝并暂停了会话。后续未复现，未确认具体字段差异。已在协调提示中明确六个必需字段及空值写法，保留严格校验和异常时暂停，不增加自动重试。
- `high` 档位曾完成整组验收，也曾在复验时超过 120 秒截止。最终使用 `medium` 完成验收，保留 120 秒截止。验收进一步要求 A、B 各一次且均成功，不能把超时后的最终回复当成通过。

这证明上述具体场景可运行，不是模型可靠性或延迟分布的统计评估。
真实写工具、持久化和旧工具迁移仍不在本次范围内。
