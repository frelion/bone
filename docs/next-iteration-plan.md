# Context 迭代：落地状态与后续工作

2026-09-10 · 当前实现基线见 [最小架构](core-simple-design.md) 与 [Context Engine V2](context-engine-v2.md)。

## 本轮已完成

| 阶段 | 已落地 | 验收重点 |
| --- | --- | --- |
| A：角色与责任 | Router 仅 Assign / Read / Clarify；Worker 规划、委派、控制后代与更新约束 | 原话独立交付；新输入在有效审阅前阻止旧回复、完成和外部写；失败与取消可解除屏障 |
| B：持久提交与恢复 | Core DurablePort 契约、Runtime 提交前门禁、App SQLite 事务、Core restore | 未持久状态不先发布；原始记录与快照分开；中断工作和 Unknown 写入不自动重放 |
| C：两层上下文 | Core Session 公共投影、独立 Session checkpoint、Session/Job 共用 compact 协议 | 组合预算；先分页；合法前缀；无收益失败；原文、未处理输入和恢复状态不受摘要破坏 |

这三个阶段已经落在代码中，不再是待实现设计。具体行为以测试和 [Core](core.md) 为准，不以测试数量作为长期规格。

## 明确采用的简化

- 每次调用读取最新已提交公共背景；没有输入接受时冻结 W。
- Context 是 Kernel 内部投影函数，没有独立 ContextEngine actor。
- 同步按需压缩；没有后台阈值策略或摘要树。
- Session 与 Job 共用模型端口和草稿协议，分别选择来源与合法范围。
- 日常计划写 Note；正式契约不被当作可随意替换的计划。
- 当前 Worker 统一模型配置；没有任务分类器或独立 resolver。
- 仅保留当前持久协议；删除旧格式迁移、历史注入与缺失来源推断。`SessionContext` 由 Core 公共记录和摘要生成。

## 当前仍保留的边界

Worker 可以依据原话纠正理解并澄清，但公共 WorkStep 尚无原子转交负责人动作。旧稿中的“误投后原子交接”是后续提案。

App 只接受当前持久协议，恢复使用 Core 记录和摘要；不从旧产品历史拼装记忆。App 仍拥有产品 Session 身份、视图、配置和跨 Session 写门禁。

必要原始输入或约束本身超限会明确失败。当前 routing 合并未关闭输入，不宣称已实现自动有界拆批。Core 使用序列化 DTO 字节预算；provider 包装、工具 schema 与输出预留仍需适配器留余量。

## 后续按需要推进

1. 质量评测：用长对话、约束变更、多 Job 和工具大结果比较分页基线与滚动摘要；观察遗漏、任务完成率、费用和延迟。
2. 输入批次：只有真实超限案例需要时增加受控拆批，保留顺序、身份与未处理原话。
3. 纠错转交：明确完成责任与在途写入归属后，再增加原子转交协议；不能简单清空 required_jobs。
4. 容量与性能：基于实测增加 provider token 估算、模型选择或后台预压缩。
5. 存储体量：单独设计惰性加载、引用闭包、retention 和 GC；checkpoint 水位不能直接充当删除线。

## 已覆盖的关键回归

Session 长历史可压缩且不泄漏私有 Note / child Published；未处理输入被历史摘要覆盖仍保持待审阅；Session 与 Job 各自能放下但组合超限时可选择 Session 压缩；压缩期间追加输入不让固定前缀失效；无收益/超限摘要明确失败并保留原文；恢复保留摘要与原始引用。

其他协议回归覆盖路由迟到结果、约束版本、取消和准备失败后的屏障回收、工具分页、durable 提交失败和恢复中断。

独立审查后的补充回归包括：永久 pending 提交下的关机期限与未确认结果；App 等待输入提交时关闭信号仍抵达 Core；局部或全局暂停、取消、重配置不让旧 Session 压缩结果终结任务；root 交付关联链及子任务权限；澄清问题与回答共同保留；超过 8 MiB 的累计历史和快照分段恢复；Core 恢复提交后、App 登记 Runtime 前再次中断的投影补齐。
