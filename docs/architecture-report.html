MODULE / 02

Session 执行器

一个 Agent 的运行状态直接放在 Engine 中。它为一个 Session 持有 Job、运行任务与写租约，并裁决每次状态改变。

  • 持有的事实revision、当前对话位置、Job 集合、共享预算与未知写。
  • 执行边界异步完成只返回结果；Engine 检查版本后决定提交或继续执行。
  • 用户接口创建、发送、观察历史、停止、恢复，保持 Session 级别。
src/runtime.rs · Engine / post / step / resume
用户只推动对话。Agent 自动组织工作。

Job A/B/C 仅表示并列的同构上下文；任务角色由当时的输入决定。一次交付结束后，Job 可以回到 Idle，后续仍能续接。

02
UNIT OF WORK

Job 是可续接的工作上下文。

理解输入、规划、摘要和工具调用使用同一种 Job 结构。共享的是一个 Agent，隔离的是每份工作需要的输入、历史与等待条件。

把工作留下来。

Job 保存待处理输入、当前输入、历史事件引用、摘要引用、精确等待目标和执行状态。正文位于 Event 的 Rig 原生消息或结果中，避免再保存一份独立对话历史。

一次根用户输入共享调用与 Job 创建额度；拆分工作、路由、规划和摘要都不会重置这份额度。

Ready

可调度

有可继续的工作，等待 Engine 启动模型调用或下一项工具动作。状态由输入、结果和控制事件共同决定。

Session 还保存一个整体 paused 标记。暂停 Session 不等于每个 Job 都必须变成 Paused；自然语言“停止”这个输入会先得到明确结算。

03
EXECUTION WALKTHROUGH

从一句输入，到一次可靠交付。

模型和工具执行异步返回结果。唯一的 Session 调度循环根据持久输入、版本与副作用状态，决定接下来能做什么。

输入 → Job → 模型 → 工具 → 交付Session / revision + 1
01

输入持久化，建立执行身份

Engine 保存用户原生输入事件，增加 Session revision，并建立根输入共享预算。首次对话才创建普通 Job；续聊进入当前对话位置。

input → root_input → Budget Session.revision += 1
固定机制示例
演示不执行模型或文件操作
输入完成，依赖的是它自己的交付事件。

CLI 等待对应 input ID 的结果。当前输入的“完成”与整个 Session 的“没有待办”分别判断；旧要求由 Agent 使用 input_resolve 明确结算。

04
LONG TASKS & RECOVERY

工作可以中断，执行事实要留下。

长任务的可靠性来自几个具体边界：指令版本、完整原文、动作启动记录、准确的依赖身份，以及对未知副作用的保守恢复。

01

新指令优先，旧结果受版本约束

输入持久化即提高 revision。旧模型响应只留下迟到记录，尚未启动的旧动作被取消。已开始的外部动作保留原 input/call 身份，其后果仍须记录。

02

等待精确绑定输入结果

wait_for 指向具体 input ID，安装等待时检查循环。旧请求 completed 或 superseded 都产生对应结算事件，等待方需要检查实际 outcome。

03

模型并行，工作区写动作串行

每个 Job 同时至多一个模型调用；不同 Job 可并行思考和执行只读操作。同一 canonical 工作区根的写入和 shell 使用跨进程写租约；订阅凭据另行串行。

04

先记意图，再启动外部调用

状态改变和事件在同一 SQLite 事务中提交。外部动作之前先保存启动意图；动作完成后若数据库提交失败，Engine 锁存故障并要求重开恢复。

05

未知写先核查，再继续

重启后保留上下文与原额度。结果未知的写操作先取得锁并核查、记录 reconciliation；其间阻止进一步写入和成功交付，避免自动重放副作用。

06

原始内容完整，工作集按需缩小

SQLite 保留原文。超限时压缩可消费的旧历史，保留未处理输入与原生工具关系；最新结果在工作模型真正消费前受保护。必要时用有界预览和原事件引用续读。

05
ABSTRACTION ACCOUNTABILITY

每个机制，都需要失败证据。

保留一个 Cargo package，按职责拆具体模块。普通函数、结构体与 Rig 原生类型承担实现；每个额外机制都要说明删掉它会失去什么。

保留的实现解决的明确需求删掉会发生什么
Engine异步结果、新指令、状态提交需要统一裁决。旧响应可能继续启动动作，多个完成路径同时改历史。
Session / Job / Budget持续工作、续接、等待关系与根输入共享额度。恢复后失去归属；拆分工作可能重置额度。
Event + SQLite保存原生内容、因果身份及原子状态。不能确定交付对应哪个输入，也不能确认动作是否已经开始。
版本与执行租约打断、跨进程所有权、取消后物理动作仍可能继续。过期动作被启动，两个 writer 同时修改同一工作区。
input_resolve新请求已经完成或替代旧要求，旧输入仍排队。旧请求再次执行，重复副作用或消耗预算。
上下文保护函数系统指令丢失、工具配对被截断、新结果陷入摘要循环。模型看不到原要求或最新源码，长任务无法持续推进。
具体搜索 / 编辑函数跨文件定位、完整 hash、基于原文件的安全局部修改。只能逐页读源码、整文件生成或依赖通用 shell。
原生模型准备与连接有效凭据、锁寿命、排队与实际请求的超时边界。认证排队误占请求超时，配置与锁生命周期失配。

查看 Rig 接入与物理执行边界
  • Rig 固定提交 063bcf0e9cee2fd5287fbb807e67d3e9d418ba0a。注册表能力直接继承；Cohere / Ollama 补原生构造接线，Bedrock / Vertex / Candle 通过可选 feature 接入。
  • 注册表与协议契约检查不等于每个 provider 都完成真实调用；本轮真实调用使用 ChatGPT 订阅的 gpt-6-luna。
  • 固定 Rig 的订阅 wire 不发送 max_output_tokens；运行时限和调用额度仍然生效，max_tokens 不能保证该路径的服务端输出上限。
  • 同根工作区租约不能阻止不配合的外部 writer；文件写入不是 OS 级 compare-and-swap。搜索游标是可校验位置，不是授权凭据，也没有整树快照隔离。
  • 自行脱离进程组或关闭继承锁描述符的后台程序，超出前台 shell 生命周期保证。
